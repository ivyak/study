explain

コード解説

実コードを読み、初学者がコードと答え合わせしながら読める解説資料を作ります。ファイル・行番号付きの引用、構造図、用語の説明、理解度チェックを含め、資料の更新時には現在のコードへ参照を合わせ直します。

対象はファイル・ディレクトリ・テーマです。保存先と読者レベルに合わせて構成を設計し、引用と図から実装をたどれるMarkdown資料を作成します。機械的な参照検査とLLMによる説明の確認を組み合わせて、既存資料の更新にも対応します。

コマンド一覧構造図詳細な解説

受付可能なコマンド一覧

Claude側のスキルです。/explainは会話からの呼び出しで、シェルコマンドではありません。対象は自然言語でも指定可能。-o/--outが未指定なら保存先を確認し、分冊構成は本文作成前に提示して承認を得る手順です。

  • /explain -o docs/catch-up src/services/export.py

    対象ファイルと出力先を指定して解説を作成します。

  • /explain -o docs/catch-up -n 14 --max-lines 250 workerの非同期処理

    連番と1ファイルの行数上限を指定。既定の上限は300行です。

  • /explain -o docs/catch-up --single --level dev このPRの変更内容

    短いテーマを1ファイルにまとめ、開発者向けに説明します。既定の読者レベルはzeroです。

  • /explain -o docs/catch-up --update 13_4 --no-quiz

    既存資料の引用・行番号を更新し、理解度チェックを省略します。

  • bash .claude/skills/explain/scripts/check_docs.sh docs/catch-up --max-lines 300 --root /path/to/repo

    行数、相対リンク、コード引用の実在・行番号、目次からの導線を検算します。

スキルの構造図

決定論：同じ入力に同じ規則を適用LLM：内容の読解・判断・生成

  1. LLM・読解／判断

    対象・保存先・構成を確認

    対象コードを読み、読者に合わせて分冊構成を設計。

  2. ユーザー確認

    分冊構成を承認

    本文作成前にファイル名・内容・目安時間を確認。

  3. LLM・読解／判断

    実コードを引用して解説

    用語、図、理解度チェックを作成し、目次を更新。

  4. 決定論・スクリプト

    check_docs.shで検算

    行数・リンク・コード参照・目次を規則で検査。

  5. LLM・読解／判断

    検算結果から修正

    参照や構成の問題を直して再検算。

検算スクリプトは解説の意味やすべてのリンク形式を検証しません。検査に通ることと、解説がコードを正しく説明していることは別です。

詳細な解説

実コードを読む

対象ファイルの全文と呼び出し元・先・型定義・テストを確認します。引用は実物のコピーを使い、リポジトリルートからの相対パスと行番号を添えます。古い設計書とコードが食い違う場合はコードを基準にし、死んだコードや仕様の罠も説明します。

初学者が自力でたどれる説明

型や関数の定義場所、言語の記法、標準ライブラリをその場で説明します。未経験者向けを既定にし、--level devなら比喩を減らして設計判断を中心にします。通常は末尾に3問の理解度チェックを付け、答えは折り畳み、対応する節へつなぎます。

分冊と構成の確認

通常は1ファイル200〜300行になるよう節を先に設計します。構成一覧を提示して承認後に本文を書きます。出力先に既存の資料があれば連番や体裁を合わせ、目次と前後ナビゲーションも更新します。出力先未指定時は書き始める前に確認します。

検算と更新

check_docs.shで機械的に検査します。行数超過や目次導線の不足は警告、リンク切れや不正なコード引用はエラーとして扱います。検査は正規表現で拾える範囲に限られ、意味の正しさはLLMが確認します。--updateでは対象コミットまたは日付を更新し、引用と行番号を取り直します。
