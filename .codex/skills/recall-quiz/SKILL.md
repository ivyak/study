# Recall Quiz

習った範囲を短時間で思い出すための教材を作る。選択式の問題や、長い計算をその場で完遂させる問題は既定にしない。問題作成はMacで行い、出題はGitHub Pagesで公開するブラウザ版アプリが担当する。学習記録は端末のブラウザ内に保存する。

## 教材の作成・更新

- 科目と授業回・学習済み範囲を特定する。各授業回は原則10問以内とし、数合わせで増やさない。必要な範囲を問数制限なしで扱うようユーザーが指定した場合は、その指定に従う。リポジトリ全PDFを一括処理しない。
- 既存解説で候補を拾い、答えと条件は講義の原資料で照合する。数式・手書きはページ画像を確認する。問題の正しさは原資料、優先度は利用可能な演習・過去問を基準にする。確認していない試験頻出度や配点は付けない。
- その分野の問題を解くときや、その先の内容を理解するときに繰り返し使う知識・解法パターンを選び、優先度の高い順に並べる。型の識別、解法の手順、適用条件、失う解、同値でなくなる変形などを優先する。その場の証明のためだけの補助計算や汎用性の低い細部は出さない。
- 問題は1問だけで意味が通るようにする。式、記号の意味、対象範囲、仮定など、回答に必要な条件をすべて問題文に書く。前後の問題、解答、補足を読んでいることを前提にしない。
- 頭の中で短く答えられる知識や解法の想起を中心にし、紙での計算、長い式変形、証明の再現を必要とする問題は出さない。計算結果より、基本形や解法の手順を問う。
- 条件を含めると読むだけで疲れる問題は、条件を削らずに問いの対象を狭めるか、出題を見送る。原則1問1判断とするが、一続きの短い解法パターンや型の一覧は1問でよい。
- 例えば、変数分離型の基本形、変数分離型の解法の手順、講義で扱う求積法の3つの型、解の関係式を二乗したときの同値性を問う。単なる基本形の想起に解法の仮定まで足す必要はないが、実際に関数で割って解く手順を問うなら、0でない区間であることを問題文に含める。
- 「この内容が言えれば正解」という短い判定基準を付ける。補足は別欄に置く。答えの見た目を覚えるだけの重複問題を増やさない。
- 簿記で仕訳が解答になる場合は、借方を左、貸方を右に置き、勘定科目を括弧で囲んで金額と並べる。金額が未指定なら `***` を使い、指定された金額は実額を記入する。勘定口座はT字型、原価計算表などは見出しと必要な合計行を持つHTMLの表で表示する。文章の列挙や空白合わせだけで済ませず、[データ仕様の簿記の解答](references/deck-format.md#簿記の解答)に従って `answerBlocks` を作る。
- 既存デッキの `sourceManifest` のハッシュと照合済みページを先に確認する。同じ資料は既存の問題・照合記録を再利用する。資料が変わったら影響範囲を読み直してから問題とハッシュを更新する。ハッシュの一致だけで初回の内容照合を済ませたことにしない。
- [データ仕様](references/deck-format.md)に従い、リポジトリの `apps/recall-quiz/decks/` にJSONを保存する。既存の内容修正は固定IDを保つ。問い・答え・正解基準などが変われば問題の `version` とデッキの `version` を上げる。別の判断を問う問題には新IDを付ける。IDを並び順から再採番しない。
- 学習履歴やコインを教材の更新で初期化しない。ユーザーが誤答記録を渡した場合は、まず曖昧な問い・前提理解不足・条件の欠落を点検し、単に問題数を増やさない。


## 簿記の用語・知識と演習問題

- 簿記は、説明欄の用語・知識と、原資料の演習問題を別の教材にする。同じ `title` を使い、`studyType` をそれぞれ `knowledge` と `exercise` にする。出題セットに混ぜない。
- 用語・知識は、説明欄に基づく「〜とは何か？」の問いにする。仕訳や表を完成させる問題は演習問題に置く。
- 演習問題は、指定された原画像の問題文、取引、条件、数値を省略・言い換えせずに使う。範例を演習にする指定があれば、範例を使う。日本語の句読点はリポジトリの指示に従う。原資料の誤植を直す場合は、根拠と修正箇所を補足に明記する。
- 一続きの範例は途中の取引だけに分割しない。前の範例の結果が必要なときは、それまでの記入を提示し、今回埋める箇所だけを空欄にする。問題を単独で解ける条件を残す。
- 演習では `promptBlocks` に原文と仕訳・勘定口座・表を順番に置く。記入欄を `null` にし、与えられた数値や見出しは文字列で残す。解答は `answerBlocks` にすべて記入し、`null` を含めない。アプリが四角い入力欄とHTMLの表を生成する。
- 演習は時間制限を設けず、原資料の順に出題する。長い問題文や表は、情報を削らず文字を小さくして読みやすくする。
- 問題数の上限よりユーザーが指定した網羅範囲を優先する。内容が変わって別の問いになる場合は新IDを付け、以前の問題は同じデッキの `retiredQuestions` に残して履歴から参照できるようにする。

## ビルドと引き渡し

リポジトリルートから実行する。初回のみアプリの依存関係を `npm ci --prefix apps/recall-quiz` で準備する。

```bash
npm run build --prefix apps/recall-quiz -- apps/recall-quiz/decks/<deck-id>.json --verify-sources
npm test --prefix apps/recall-quiz
```

ビルドは数式をMathMLへ変換し、画面、問題JSON、原典画像、動物画像を `apps/recall-quiz/output/site/` に生成する。原典画像はMacで生成し、原資料のハッシュとページでキャッシュを再利用する。初回生成には原資料とSwiftが必要。原資料のハッシュ、ページ参照、数式に問題があれば修正して再実行する。原資料が手元にない場合は照合未実施を明示し、ハッシュ確認を通過したと報告しない。画像なしの配布を選ぶ場合だけ `--without-source-images` を指定する。

- 公開時は教材指定なしで全教材をビルドする。検証後に `npm run deploy --prefix apps/recall-quiz` でGitHub Pagesを更新する。公開を依頼されていなければ勝手に公開しない。操作は[アプリの手順](../../../apps/recall-quiz/README.md)を参照する。
- `npm run dev --prefix apps/recall-quiz` でHTTPプレビューを開き、問題、解答、数式、原典画像のページ対応、解答内のトグル開閉と拡大縮小、終了導線を確認する。原典は解答の下で展開し、別画面に切り替えない。localhostと公開サイトの学習記録は別に保存される。
- 教材のIDを保ち、ブラウザの回答履歴やコインを更新時に初期化しない。教材を端末へ手動で取り込む操作は不要。Scriptable向けの `Quiz.js` や `.compiled.json` は生成しない。
- 変更の範囲、問題数、出典、未確認の範囲、公開の有無を短く伝える。iPhoneの実機を操作していなければ、Safariでの中断復帰やファイルの読み書きを実機確認済みとしない。

画面だけの変更では教材を作り直さない。教材作成だけの依頼で、公開ホスティング、通知送信サービス、アカウント設定を追加しない。
