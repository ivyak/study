## 5.1 DP とは「途中結果を表に書き溜めながら進む」こと

**DP（動的計画法, Dynamic Programming）** は、名前がいかついだけで、やっていることは

> **表を 1 マスずつ埋めていく。各マスは、すでに埋めたマスから計算する。**

これだけです。全探索だと同じ計算を何度もやってしまうところを、
**一度計算した答えを表に書いておいて使い回す**ので速くなります。

```
   全探索（指数時間）              DP（多項式時間）
   ┌─────────────┐              ┌───┬───┬───┬───┬───┐
   │ 枝分かれを全部  │              │ 0 │ 1 │ 1 │ 2 │ 3 │  ← 1 列ずつ埋める
   │ 最後までたどる  │   →          └───┴───┴───┴───┴───┘
   │  2^N 通り     │                 各マスは左のマスから O(1) で出る
   └─────────────┘                 合計 O(N)
```

### DP を書くときに決める 3 つ

```
  ① dp[i] が「何を表すか」を日本語で決める   ← ここが全部
  ② 初期値（何も選んでいない状態）を決める
  ③ 遷移（dp[i] を、すでに求めた値からどう作るか）を決める
```

**①で詰まったら、②③はいくら考えても出てきません。** 逆に①が決まれば③はほぼ自動です。
①を決めるコツは、**「最後の 1 手で場合分けする」**こと。次の節で実際にやります。

## 5.2 いちばん簡単な DP — 階段の上り方

> 階段が N 段ある。1 歩で 1 段か 2 段のぼれる。のぼり方は何通り？

```
  ① dp[i] = 「i 段目にたどり着く方法の数」
  ② dp[0] = 1（何もしていない状態が 1 通り）
  ③ i 段目に来る直前は、i-1 段目か i-2 段目のどちらか
     → dp[i] = dp[i-1] + dp[i-2]
```

③が「**最後の 1 手で場合分け**」です。「最後に 1 段のぼったか、2 段のぼったか」で分けています。

```python
N = int(input())
dp = [0] * (N + 1)
dp[0] = 1
for i in range(1, N + 1):
    dp[i] += dp[i - 1]
    if i >= 2:
        dp[i] += dp[i - 2]
print(dp[N])
```

`if i >= 2` を書かないと `dp[-1]` になります。**Python の負の添字はエラーにならず、
末尾の要素を読んでしまう**ので、気づかないまま WA になります。DP での最頻出バグです。

## 5.3 ナップサック DP — D 帯の主役

> N 個の品物があり、品物 i は重さ `w[i]`、価値 `v[i]`。重さの合計が W 以下になるように選んで、
> 価値の合計を最大にせよ。（制約: N ≤ 100、W ≤ 10^5）

貪欲（価値の高い順に取る）では解けません。反例がすぐ作れます。

```
   W = 10
   品物A: 重さ 10、価値 11   ← 単体では最強
   品物B: 重さ  5、価値  6
   品物C: 重さ  5、価値  6
   貪欲だと A を取って 11。正解は B+C で 12
```

DP の設計はこうです。

```
  ① dp[i][j] = 「i 個目までを見て、重さの合計が j のときの、価値の最大値」
  ② dp[0][0] = 0、それ以外は -1（到達不能）または 0
  ③ i 個目を「使わない」→ dp[i-1][j] がそのまま
     i 個目を「使う」  → dp[i-1][j - w[i]] + v[i]
     この 2 つの max
```

```python
N, W = map(int, input().split())
wv = [tuple(map(int, input().split())) for _ in range(N)]

dp = [[0] * (W + 1) for _ in range(N + 1)]
for i in range(N):
    w, v = wv[i]
    for j in range(W + 1):
        dp[i + 1][j] = dp[i][j]                       # 使わない
        if j >= w:                                    # 使える場合だけ
            dp[i + 1][j] = max(dp[i + 1][j], dp[i][j - w] + v)
print(dp[N][W])
```

計算量は **O(NW)**。N=100, W=10^5 なら 10^7 で、PyPy なら通ります。

> **`dp = [[0] * (W+1)] * (N+1)` と書いてはいけません。**
> `*` でリストを増やすと**同じリストへの参照が N+1 個並ぶ**ので、1 行書き換えると
> 全行が書き換わります。必ず `[[0] * (W+1) for _ in range(N+1)]` と内包表記で作ってください。
> → [§8.6 2 次元配列の罠](./01_8_Python落とし穴と提出前チェックリスト.md)

### 1 次元に圧縮する（メモリが足りないとき）

`dp[i+1]` は `dp[i]` しか使わないので、1 次元で使い回せます。
**その場合は j のループを逆順にする**のが鉄則です。

```python
dp = [0] * (W + 1)
for w, v in wv:
    for j in range(W, w - 1, -1):     # 逆順！
        dp[j] = max(dp[j], dp[j - w] + v)
print(dp[W])
```

昇順にすると `dp[j-w]` が「**今回すでに更新済み**」の値になり、同じ品物を何度も使えてしまいます。
（逆に「同じ品物を何個でも使ってよい」問題では、**わざと昇順**にします。これが個数無制限ナップサック。）

## 5.4 経路数 DP — グリッドを進む

> H×W のマス目。左上から右下へ、右か下にしか動けない。`#` は通れない。経路は何通り？

```
  ① dp[i][j] = 「(i, j) に到達する経路の数」
  ② dp[0][0] = 1
  ③ dp[i][j] = dp[i-1][j] + dp[i][j-1]   （上から来たか、左から来たか）
```

```python
H, W = map(int, input().split())
G = [input() for _ in range(H)]
MOD = 10 ** 9 + 7

dp = [[0] * W for _ in range(H)]
dp[0][0] = 1
for i in range(H):
    for j in range(W):
        if G[i][j] == "#":
            dp[i][j] = 0
            continue
        if i > 0:
            dp[i][j] += dp[i - 1][j]
        if j > 0:
            dp[i][j] += dp[i][j - 1]
        dp[i][j] %= MOD
print(dp[H - 1][W - 1])
```

`MOD` については [§7.4 mod と逆元](./01_7_D問題その3_数学_約数と素数とmod.md) で説明します。
「答えを 998244353 で割った余りを出力せよ」と書いてあったら、**足すたびに `%= MOD`** します。

`if i > 0` / `if j > 0` が、§5.2 と同じ「負の添字を避ける」ガードです。

## 5.5 区間 DP と「最後の 1 手」の言い換え

D 帯では、次のような言い換えで DP に落ちる問題も出ます。

| 問題の形 | dp[i] の置き方 |
|---|---|
| 「i 番目まで見たときの最大／最小」 | `dp[i] = i 番目まで見たときの答え` |
| 「ちょうど j 使ったときの…」 | `dp[i][j] = i 番目まで見て j 使ったときの答え` |
| 「区間 [l, r] をまとめたときの…」 | `dp[l][r] = 区間 [l,r] の答え`（O(N³) になりがち、N ≤ 300 程度） |
| 「集合 S を訪問済みのときの…」 | `dp[S][v] = 集合 S を訪れて今 v にいる`（**bit DP**、N ≤ 15 程度） |

### bit DP の形だけ

`N ≤ 15〜18` という制約で「全部の順番を試したいが N! は無理」というときに使います。
集合を §3.4 と同じ **bit（整数の 2 進表記）**で表します。

```python
# dp[S][v] = 集合 S の頂点を訪問済みで、今 v にいるときのコスト最小値
INF = float("inf")
dp = [[INF] * N for _ in range(1 << N)]
dp[1][0] = 0                       # 頂点 0 だけ訪問済み、今 0 にいる
for S in range(1 << N):
    for v in range(N):
        if dp[S][v] == INF:
            continue
        for u in range(N):
            if S & (1 << u):       # u はもう訪問済み
                continue
            nS = S | (1 << u)      # u を訪問済みに加える
            dp[nS][u] = min(dp[nS][u], dp[S][v] + cost[v][u])
```

計算量は `O(2^N × N²)`。N=15 なら 3.2万 × 225 ≒ 7×10^6 で通ります。
`float("inf")` は「無限大」で、min を取る初期値として使います
（`int` と比較できます。ただし `%` などの整数演算はできません）。

## 5.6 DP が書けたあとの確認

```
□ dp の添字の範囲は足りているか（N ではなく N+1 で取る場面が多い）
□ 負の添字（dp[i-1] で i=0）をガードしたか
□ 初期値は「到達不能」と「値 0」を区別できているか（0 と INF / -1 の使い分け）
□ 2 次元配列を [[0]*W]*H で作っていないか
□ 答えは dp[N] か、dp の中の max か（最後のマスとは限らない）
```

4 つ目と 5 つ目がとくに事故ります。「i 個ちょうど使う」なら `dp[N][K]`、
「何個でもよい」なら `max(dp[N])` のように、**問題文の言い回しで答えの取り出し方が変わります**。

## 理解度チェック

<details>
<summary><b>Q1.</b> DP を設計するとき、3 つ（定義・初期値・遷移）のうちどれが最重要？ なぜ？</summary>

**A.** **①の定義（dp[i] が何を表すか）**。定義が日本語で言い切れれば、遷移は
「最後の 1 手で場合分け」すればほぼ自動的に出る。逆に定義が曖昧なまま遷移を考えても
永遠に出てこない。困ったら「i 番目まで見て、○○が j のときの答え」の形に当てはめる。→ §5.1
</details>

<details>
<summary><b>Q2.</b> ナップサック DP を 1 次元に圧縮するとき、`for j in range(W, w-1, -1)` と逆順にする理由は？</summary>

**A.** 昇順にすると `dp[j - w]` が**今回の品物ですでに更新された値**になり、
同じ品物を 2 回以上使った状態が混ざるから。逆順なら `dp[j-w]` はまだ前の品物までの値のまま。
なお「同じ品物を何個でも使ってよい」問題では、**わざと昇順**にするとそれが正解になる。→ §5.3
</details>

<details>
<summary><b>Q3.</b> `dp = [[0] * (W+1)] * (N+1)` で作った DP 表が、1 マス書き換えると全行変わる。なぜ？</summary>

**A.** リストの `*` は**中身をコピーせず、同じリストへの参照を並べる**だけだから。
`dp[0]` も `dp[1]` も同一のリストを指しているので、`dp[0][3] = 5` は全行に反映される。
`[[0] * (W+1) for _ in range(N+1)]` と内包表記で毎回新しいリストを作ること。→ §5.3 / §8.6
</details>
