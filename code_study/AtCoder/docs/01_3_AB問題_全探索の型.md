## 3.1 A・B で失う点数は、ほぼ全部が「読み違い」と「境界」

A・B は考察がほぼ要りません。それでも WA を出すときの原因はだいたいこの 5 つです。

| 原因 | 具体例 | 防ぎ方 |
|---|---|---|
| **1-indexed / 0-indexed のズレ** | 「i 番目」が問題文では 1 から、Python は 0 から | 入力直後に方針を決めて紙にメモ |
| **境界（以上／より大きい）** | 「X 以上」なのに `> X` と書く | 問題文の該当行をコピペしてコメントに貼る |
| **端のケース** | N = 1、全部同じ値、答えが 0 | 自分で N=1 の入力を作って試す |
| **出力形式** | `Yes` を `YES` と書く | 問題文からコピペする |
| **切り上げ／切り捨て** | `A / B` で小数になる | 整数除算 `//` と切り上げの型（§3.2） |

**「入力例が通ったから提出」で WA になるのは、入力例が端のケースを含んでいないから**です。
提出前に **N が最小のケース**を自分で作って動かす。これだけで WA がかなり減ります。

## 3.2 覚えておく算術の型

### 切り上げ除算

Python の `/` は小数（float）を返し、`//` は**切り捨て**です。切り上げは自分で書きます。

```python
# A を B で割った切り上げ
ans = -(-A // B)        # 定番の書き方
ans = (A + B - 1) // B  # こちらでも同じ（A, B が正のとき）
```

`-(-A // B)` は「マイナスにしてから切り捨て、戻す」ことで切り上げになります。
`math.ceil(A / B)` でも書けますが、**A が 10^18 のような巨大な数だと float の精度で狂います**。
整数のまま計算する上の 2 つを使ってください（→ [§8.4 float の罠](./01_8_Python落とし穴と提出前チェックリスト.md)）。

### 負の数の割り算に注意

```python
print(-7 // 2)        # -4  （Python の // は「小さいほうへ」丸める）
print(int(-7 / 2))    # -3  （こちらは 0 のほうへ丸める）
```

**問題文が「切り捨て」と言っているとき、負の数でどちらを指すかは問題による**ので確認します。

### その他

```python
abs(x)              # 絶対値
divmod(a, b)        # (商, 余り) を同時に
max(A) - min(A)     # 最大と最小の差
sum(A)              # 合計。Python の int は桁あふれしない（§8.5）
```

## 3.3 二重ループ全探索 — B の主力

「全部のペアを試す」型。`N ≤ 2000` くらいまでなら Python でも通ります（§2.4）。

```python
# 例: N 個の数から 2 個選んだときの和の最大値
N = int(input())
A = list(map(int, input().split()))

ans = 0
for i in range(N):
    for j in range(i + 1, N):    # j は i より後ろだけ見る
        ans = max(ans, A[i] + A[j])
print(ans)
```

`range(i + 1, N)` がポイントです。`range(N)` にすると
**同じペアを 2 回数える（(0,1) と (1,0)）うえに、自分自身とのペア (0,0) も含んでしまう**。

```
  j の範囲を i+1 からにすると、調べるのは右上の三角だけ

      j→  0   1   2   3
   i  0   -   ○   ○   ○
   ↓  1   -   -   ○   ○
      2   -   -   -   ○
      3   -   -   -   -
```

回数は `N(N-1)/2` 回。オーダーは O(N²) のままですが、無駄と重複が消えます。

## 3.4 bit 全探索 — 「選ぶ／選ばない」を全部試す

**N ≤ 20〜25 という不自然に小さい制約を見たらこれ**（§2.4）。
N 個のものそれぞれについて「選ぶ／選ばない」を決めると、組み合わせは `2^N` 通りです。

その `2^N` 通りを、**0 から 2^N - 1 までの整数の 2 進表記**で表すのがこの技です。

```
  N = 3 のとき、bit = 5 は 2 進で 101
    ┌───┬───┬───┐
    │ 1 │ 0 │ 1 │
    └───┴───┴───┘
      ↑   ↑   ↑
     2番 1番 0番        → 0 番目と 2 番目を「選ぶ」という意味になる
```

書き方の型がこれです。**丸暗記してください。**

```python
# 例: N 個の数から何個か選んで、合計をちょうど X にできるか
N, X = map(int, input().split())
A = list(map(int, input().split()))

ok = False
for bit in range(1 << N):          # 1 << N は 2^N のこと
    total = 0
    for i in range(N):
        if bit & (1 << i):         # i 番目の bit が立っている ＝ i 番目を選ぶ
            total += A[i]
    if total == X:
        ok = True
print("Yes" if ok else "No")
```

登場する 3 つの記号を説明します。

| 書き方 | 意味 |
|---|---|
| `1 << N` | 1 を左に N ビットずらす ＝ **2^N**。`1 << 3` は 8 |
| `1 << i` | i 番目の bit だけが 1 になっている数。`1 << 2` は `100`（＝ 4） |
| `bit & (1 << i)` | **AND**。`bit` の i 番目の bit が 1 なら 0 以外、0 なら 0 を返す |

`if bit & (1 << i):` は「**bit の i 番目が立っているか**」の定型句です。
`!= 0` は省略できます（Python では 0 以外が真）。

計算量は `O(2^N × N)`。N = 20 なら `10^6 × 20 = 2×10^7` で、PyPy なら通ります。
**N = 25 を超えると厳しい**ので、その場合は別の解法（DP など、§5）を疑ってください。

## 3.5 順列全探索 — N ≤ 10 のとき

「並べ方を全部試す」型。巡回セールスマン風の問題で出ます。

```python
from itertools import permutations

N = int(input())
A = list(map(int, input().split()))

for perm in permutations(range(N)):   # 0..N-1 の並べ方を全部
    # perm は (0, 2, 1) のようなタプル
    ...
```

`N! ` 通りなので、**N = 10 で 362 万通り**、N = 11 で 4000 万通り。**10 が上限**と思ってください。

`itertools` には他にもよく使うものがあります。

```python
from itertools import combinations, product

combinations(A, 2)          # A から 2 個選ぶ組み合わせ（順序なし）
product(range(3), repeat=4) # 0,1,2 から 4 個を重複ありで選ぶ ＝ 3^4 通り
```

`product(..., repeat=N)` は「各マスに K 通りの選択肢」の全探索に使えます（**K 進法全探索**）。

## 3.6 文字列操作の定石

A・B は文字列問題も多いので、使うものだけまとめます。

```python
S = input()

len(S)                 # 長さ
S[0], S[-1]            # 先頭、末尾
S[1:4]                 # 1 文字目から 3 文字目（4 は含まない）
S[::-1]                # 逆順。回文判定に使う
S.count("a")           # "a" の個数
S.replace("a", "b")    # 置換（元の S は変わらない。戻り値を受け取る）
S.upper(), S.lower()   # 大文字／小文字
S.split()              # 空白で分割
"".join(L)             # リスト L を連結
ord("a"), chr(97)      # 文字 ↔ 文字コード（'a' は 97、'A' は 65）
ord(c) - ord("a")      # 'a'〜'z' を 0〜25 に変換。カウント用の配列の添字にする
```

**Python の文字列は書き換えられません。** `S[0] = "x"` はエラーです。
書き換えたいときはリストにします。

```python
L = list(S)      # ['a', 'b', 'c']
L[0] = "x"
S = "".join(L)   # 文字列に戻す
```

### 回文判定

```python
print("Yes" if S == S[::-1] else "No")
```

### 文字の出現回数を数える

```python
from collections import Counter
cnt = Counter(S)        # {'a': 3, 'b': 1, ...} のように数えてくれる
print(cnt["a"])         # 無い文字を引いても 0（KeyError にならない）
print(cnt.most_common(1))  # [('a', 3)] 最頻の 1 個
```

`Counter` は**辞書の仲間**で、無いキーを引くと 0 を返すのが便利なところです。
C 問題以降でも多用します（§4.6）。

## 3.7 A・B の提出前チェック（30 秒）

```
□ 出力の文字列を問題文からコピペしたか（Yes / No の大文字小文字）
□ 1-indexed と 0-indexed を取り違えていないか
□ N = 1（最小ケース）で動かしたか
□ 「以上」「より大きい」を >= と > で取り違えていないか
□ 割り算は // か、切り上げが必要ではないか
```

A・B は**速く出すより、1 回で通す**ほうが得です（誤答 1 回 = 5 分、§1.1）。

## 理解度チェック

<details>
<summary><b>Q1.</b> 「N 個から 2 個選ぶ」二重ループで、内側を `range(N)` ではなく `range(i+1, N)` にする理由は？</summary>

**A.** `range(N)` だと (i, j) と (j, i) を両方数えてしまい、さらに **i == j の「自分自身とのペア」**
まで含んでしまう。最大値を取るだけなら害が出にくいが、
「ペアの個数を数える」問題ではそのまま答えが 2 倍＋N になって WA する。→ §3.3
</details>

<details>
<summary><b>Q2.</b> `for bit in range(1 << N)` の中で「i 番目を選んだか」を判定する定型句は？ N の上限はいくつまで？</summary>

**A.** `if bit & (1 << i):`。`1 << i` は i 番目だけ 1 が立った数で、AND を取ると
その桁が立っているときだけ 0 以外になる。計算量は O(2^N × N) なので、
**N ≤ 20〜25 が上限**。それより大きい N で出てきたら bit 全探索ではない。→ §3.4 / §2.4
</details>

<details>
<summary><b>Q3.</b> `ans = math.ceil(A / B)` と書いたら、大きな入力だけ WA した。なぜ？ どう直す？</summary>

**A.** `A / B` が **float（浮動小数点数）**になるため。float は約 15〜16 桁しか正確に持てず、
A が 10^18 級だと割り算の時点で誤差が出て、切り上げ結果が 1 ずれる。
`-(-A // B)` と書けば整数のまま計算されて誤差ゼロ。
**競プロでは「割り算で float を経由しない」が原則**。→ §3.2 / §8.4
</details>
