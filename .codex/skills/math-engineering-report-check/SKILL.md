# 数理工学実験レポートを点検する

完成した `.tex` と、その入力ファイル、提出するコード、図、実験データを対象にする。ユーザーが指定した実験テーマを確認し、テーマ番号と教材の章番号を混同しない。原典は `Kyoto_Univ/[2026後期月３]数理工学実験/授業資料/数理工学実験2026.pdf` と `Kyoto_Univ/[2026後期月３]数理工学実験/授業資料/数理工学実験ガイダンス資料2026.pdf`。このリポジトリにない場合は、ユーザーが指定する原本を確認する。解説HTMLや過去のひな形は原典の代わりにしない。

最初に [references/review-criteria.md](references/review-criteria.md) を読む。そこには、この依頼で重視するレポート書法と、2026年ガイダンスの規則・出典上の区別がある。教員の追加指示や新しい配布資料があれば確認し、適用範囲と優先関係を示す。存在を確認していない規則を補わない。

## 点検の進め方

1. 対象章の全ページを原本で読み、本文中および章末の実験課題・設問・小問・指定条件を列挙する。PDFの文字抽出は数式や日本語を壊すことがあるので、各問題文をページ画像で照合する。必須、任意・発展、判定不能を区別する。問題ごとに教材のPDFページと、印刷ページ番号が異なる場合はその両方を記録する。
2. `\input`、`\include`、図、表、参考文献ファイルを含めてレポートを読み、問題文の明記と回答箇所を小問単位で対応させる。問題文は題意・条件・数式・数値・評価対象が原典と一致するか確認する。省略や言い換えで意味が変わっていれば指摘する。
3. 各小問について、手法、実装、入力条件、計算結果、理論値や妥当な基準との比較、考察が要求に足りるか検証する。式変形、次元・単位、物理量と記号の初出定義、境界条件、初期条件、誤差、軸・凡例、再現に必要な設定を必要な範囲で確認する。事実、推測、結論が飛躍していないか確認する。
4. 提出予定のコード・データがあれば、本文のアルゴリズム、パラメータ、図表、数値と照合する。軽量で安全な再実行や理論値との検算が可能なら行う。実行できない場合は原因と未検証範囲を記す。コードの動作確認を、存在や見た目だけで済ませない。
5. 利用可能なLaTeX環境があればビルドし、ログのエラー・警告と生成PDFの図表、文字、参照、ページ体裁を確認する。環境がない場合はソース上の確認範囲を明示する。既存の原稿・コードを修正する依頼がなければ、点検だけ行う。
6. [references/review-criteria.md](references/review-criteria.md) の構成・文章・引用・AI利用・提出物の基準を照合する。AI使用の明白な痕跡や宣言との矛盾は具体箇所を示す。文体だけを根拠に無申告利用を断定しない。AI利用歴そのものを証明できない場合は「要確認」とする。

## 結果の出し方

冒頭に、対象ファイル、原典の版、読んだ範囲、実行・ビルドの可否を示す。次に設問ごとの対応表を作り、**必須／任意、原典ページ、レポート位置、問題文、回答、結果・検証、判定**を記す。判定は「充足／要修正／未回答／未確認」を用いる。

指摘を重大度順に並べ、各項目に原稿のファイルと行、原典ページまたはガイダンスページ、何が不足・矛盾しているか、具体的な修正方針を付ける。重大度は、提出要件や必須設問の欠落・誤答を「重大」、再現性や解釈に影響する欠陥を「重要」、体裁・推敲を「軽微」とする。任意設問の未回答は必須違反としない。確認できない事項を合格や違反と判定せず、残る確認事項として別記する。採点・合格を保証しない。
