# クイズ教材のJSONを作る

[JSONの雛形](assets/deck-template.json)を読み、指定された科目と授業回の教材を作る。別のスキルに依存せず、このファイルと雛形だけで作成できる。

## 保存先と完了時の返答

このMacのリポジトリは `/Users/akito_inoue/private_project/study`。完成した教材は次の場所へUTF-8、スペース2つのインデントで保存する。

```text
/Users/akito_inoue/private_project/study/apps/recall-quiz/decks/<教材ID>.json
```

- JSONをチャットに貼るだけで終えず、ファイルを作れる環境では実際に保存する。
- 保存後はファイルを読み直してJSONとして解析できることを確認する。
- 最終回答で、科目、授業回、問題数、作成したファイルの絶対パスを伝える。ファイルへのリンクが使える環境ではリンクも付ける。
- 出典や条件に未確認の点があれば、未確認の内容と下書きの保存先を伝える。完成扱いにしない。
- このMacのファイルを操作できないAIは、ダウンロード可能なJSONを作り、上記の配置先とファイル名を伝える。添付ファイルを作れない場合はJSON全文を示す。Macへの保存を実施したとは言わない。
- JSONの作成と公開は別の作業。公開の依頼がなければ公開しない。作成だけで公開サイトに反映したとは伝えない。

返答の例は次の形にする。値は実際の作業結果に置き換える。

```text
○○の第○回、○問を作成しました。
保存先は /Users/akito_inoue/private_project/study/apps/recall-quiz/decks/○○-lesson○○.json です。
原資料の照合とJSONの確認は完了しています。公開サイトは未更新です。
```

## 対象と問題の作り方

- 資料と出題範囲を確認する。指定がなければスライド資料1件を1回分とし、PDFの1ページごとには分けない。科目や資料が判断できなければ、不足している情報だけを聞く。
- 各回10問以内。数合わせで増やさず、頭の中で短く答えられる1問1答にする。
- 定義、公式、式の型、適用条件、解法の手順、変形で失う解を優先する。選択式、長い計算、証明全文の再現は既定にしない。
- 1問だけで答えられるよう、記号の意味と必要な仮定を問題文に含める。長くなる場合は条件を削らず、問う対象を狭める。
- 短い解答と、何が言えれば正解かという自己判定基準を付ける。補足は別欄にする。
- 原資料で答えと適用条件を確認する。数式や手書きはページ画像も読む。演習や過去問があれば問題選定に使い、確認していない頻出度や配点を書かない。
- リポジトリを読める場合は、対象科目の既存JSONを先に確認する。既存の問題との重複を避け、同じ科目の `title` を引き継ぐ。既存教材で授業回の番号がずれている場合は、クイズの連番を保ち、元資料の回を `subtitle` と `scope` に記す。

## JSONの各項目

教材1回分を1ファイルにする。雛形の `__...__` をすべて実際の値へ置き換える。教材IDと問題IDの `replace-subject` も科目に合う固定の英小文字へ変更する。雛形そのものを `decks` に置かない。

| 項目 | 書く内容 |
| --- | --- |
| `schemaVersion` | 常に整数の1。 |
| `id` | 他の教材と重複しない固定ID。英小文字、数字、ハイフンを使う。例は `thermo-lesson06`。 |
| `version` | 新規教材は1。既存教材の内容を変更するときは増やす。 |
| `title` | 科目名。アプリでは同じ文字列の教材を同じ科目にまとめる。 |
| `subtitle` | `第6回 · 範囲名`の形。既存科目ではクイズの連番を引き継ぐ。 |
| `scope` | 元資料、対象ページ、作成した範囲、対象外の範囲。 |
| `sourceManifest` | 原資料ごとの照合記録の配列。 |
| `sourceManifest[].file` | 原資料のリポジトリ相対パス。先頭に絶対パスを付けない。 |
| `sourceManifest[].sha256` | 原ファイルの実際のSHA-256。小文字の16進数64文字。推測やダミー値を書かない。 |
| `sourceManifest[].pageCount` | PDF全体の物理ページ数。画像1枚なら1。 |
| `sourceManifest[].reviewedPages` | 実際に内容を確認した物理ページ番号の配列。1から数え、出題に使う全ページを含める。 |
| `sourceManifest[].method` | 実際に行った照合方法。ハッシュ確認だけで内容を照合したことにしない。 |
| `questions` | 問題の配列。1問以上、10問以内。 |
| `questions[].id` | 他の教材の問題とも重複しない固定ID。例は `thermo-l06-q01`。 |
| `questions[].version` | 新規問題は1。問い、答え、判定基準などを変更するときは増やす。 |
| `questions[].prompt` | 問題文。 |
| `questions[].answer` | 短い解答。 |
| `questions[].answerBlocks` | 簿記の仕訳・勘定口座・表の表示データ。該当する場合だけ追加する。 |
| `questions[].criterion` | 自己判定基準。 |
| `questions[].explanation` | 補足。不要でも空文字を残す。 |
| `questions[].sources` | 出典の配列。各要素に `file` と `page` を書く。 |
| `questions[].sources[].file` | `sourceManifest` にある原資料のファイル名だけ。フォルダのパスは付けない。 |
| `questions[].sources[].page` | 1から数えた物理ページ番号。画像1枚なら1。 |

JSONにコメントや末尾の余分なカンマを入れない。数式は `\( ... \)` で囲み、JSONではバックスラッシュを二重にする。JSONファイルでの記述例は `"\\(x^2\\)"`。

HTML、`promptHtml`、`answerHtml`、`criterionHtml`、`explanationHtml`、`sourceImages`、`imageKey`、`renderVersion` は書かない。表示用の項目と原典画像はアプリのビルドが生成する。

既存問題の修正では同じ問題IDを保ち、問題の並び順が変わっても再採番しない。別の判断を問うなら新しいIDにする。既存教材や問題を上書きする前に内容を読み、今回の依頼に関係のない問題、回答履歴、コインを消さない。

## 簿記の解答

仕訳が解答になるときは、借方を左、貸方を右に置き、勘定科目を括弧で囲んで金額と並べる。勘定口座はT字型、原価計算表などは見出しと必要な合計行を持つHTMLの表で表示できるデータを作る。文章の列挙や空白合わせだけで済ませない。

通常の `answer` を残し、`answerBlocks` に次の構造を追加する。アプリのビルドがHTMLを生成するため、`answerHtml` や任意のHTMLは書かない。金額が未指定の場合だけ `***` を使い、指定された金額は実額を入れる。借方・貸方の金額の意味は `note` に書ける。

```json
"answerBlocks": [
  {
    "type": "journal",
    "caption": "賃金給料の支払い",
    "debit": [{ "account": "賃金給料", "amount": "***" }],
    "credit": [
      { "account": "預り金", "amount": "***" },
      { "account": "現金", "amount": "***" }
    ],
    "note": "賃金給料は控除前の総額。預り金は控除額、現金は差引支払額。"
  }
]
```

- `journal` は1つの仕訳。`debit` と `credit` の両方に1行以上を入れ、金額は文字列にする。複数の仕訳は別のブロックにする。
- `ledger` はT字型の勘定口座。`caption` に勘定名を入れ、`debit` と `credit` は上と同じ構造で相手科目と金額を記す。片側に記入がなければ空配列にできる。
- `table` は一般の表。`headers` に列見出しの文字列配列、`rows` に同じ列数の文字列配列を並べる。任意の `totalRows` に合計行の0始まりの行番号を入れる。
- `caption` と `note` は任意の文字列。ただし `ledger` では `caption` が必要。

表の数値と左右の配置を原資料で確認し、文章の `answer` と食い違わないようにする。表示形式だけを整える変更では問題IDと問題の `version` を維持し、デッキの `version` を更新する。

## 出典の確認ができない場合

原ファイル、ハッシュ、ページ数、出典ページ、内容照合のいずれかを確認できなければ、完成した教材として `decks` に保存しない。作れる範囲の問題を次の場所に下書きとして保存し、未確認の項目を明記する。

```text
/Users/akito_inoue/private_project/study/apps/recall-quiz/drafts/<教材ID>.json
```

下書きでは未確認の項目に雛形の置換用文字列を残してよい。ページ数やページ番号も、雛形の1を確認済みの値として扱わない。完成版に移す前にすべて確認する。ファイルを操作できないAIは下書きのJSONを渡し、Mac側の配置先が `drafts` であることを伝える。

## Macでの検証と反映

Macとリポジトリを操作できる場合、SHA-256は `shasum -a 256 '原資料のパス'` などで実際に計算する。完成した教材では、少なくともJSONの解析、IDの重複、10問以内、出典ページの範囲、照合記録と出典の一致を確認する。

アプリへの追加も依頼されている場合は、リポジトリ直下で全教材をビルドし、テストとHTTPプレビューを確認する。教材を保存するだけの依頼では、ビルドや公開が済んだと誤解させない。

```bash
npm run build --prefix apps/recall-quiz -- --verify-sources
npm test --prefix apps/recall-quiz
```

スキルを使うAIの環境で実施できない検証は、実施したと報告しない。リポジトリを変更した場合はそのリポジトリの指示に従い、今回の変更だけをコミットする。
