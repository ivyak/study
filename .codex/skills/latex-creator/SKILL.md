# LaTeX文書の作成

作成前に [assets/sample.tex](assets/sample.tex) を読む。このファイルは `Kyoto_Univ/[2026後期月３]数理工学実験/テーマ2_連続最適化/sample.tex` から移動した原本であり、LaTeX文書の基本テンプレートとして使う。

## 必須の冒頭設定

新規作成する `.tex` には、`assets/sample.tex` の先頭から次のコメントブロック末尾までを**省略・変更せず、そのままコピーする**。

```latex
%
% 以後をレポート課題ごとに書き換える。
%
```

この必須範囲には以下がすべて含まれる。

- `\documentclass[a4j]{jarticle}`
- `graphicx`、`amsmath,ascmac`、`bm`、`algorithm,algorithmic`、`listings` の各 `\usepackage`
- `language={C}` から `lineskip=-0.5ex%` までの **`\lstset` 全設定**（文字スタイル、枠、折り返し、列幅、行番号、左右余白、行間を含む）
- `\renewcommand{\lstlistingname}{コード}` と `\renewcommand{\lstlistlistingname}{コード目次}`
- 上記の「以後をレポート課題ごとに書き換える」コメントブロック

必要な追加パッケージやマクロは、このコメントブロックの後、`\begin{document}` の前に追加する。コードの言語がC以外なら、冒頭の既定設定を保ち、各 `lstlisting` や `\lstinputlisting` のオプションで `language=Python` などを指定する。

ユーザーが今回の依頼で別の文書クラス・テンプレート・設定を明示した場合は、その指示を優先する。それ以外では、環境や好みを理由に必須設定を別のクラス・パッケージ構成へ置き換えない。

## 本文の作り方

- 必須範囲より後を依頼内容に合わせて書き換える。タイトル・氏名・学籍番号・日付をサンプルの値のまま成果物に残さず、不明な情報は記入欄にする。
- サンプルの書き方をできるだけ採用する。数式は `align` と `\label`・`\eqref`、表は `table`・`tabular`、図は `figure`・`\includegraphics`、コードは `lstlisting` または `\lstinputlisting` を基本とし、図表・コードにはキャプションとラベルを付け、本文から参照する。参考文献がある場合は `thebibliography`・`\cite` の例を参考にする。
- サンプルは組版の参考であり、課題の問題文や実験結果の根拠ではない。例示の文章・数値・文献を無関係な成果物に残さない。不要な章や環境は追加しない。
- `sample.eps` と `sample.c` はサンプル本文の参照例であり、このスキルには同梱していない。成果物で実際に使うファイルへ置き換えるか、不要な参照を削除する。
- 数理工学実験など、内容に関する専用スキルも適用される場合は、その内容上の指示とこのスキルの組版設定を併用する。

## 確認

保存前に、必須範囲が原本と一致し、サンプルの仮情報や存在しない外部ファイルへの参照が残っていないことを確認する。

`.tex` ファイルを作成・更新しても、自動でビルド（コンパイルやPDF生成）を実行しない。確認はソースの静的な点検にとどめ、保存した `.tex` の場所と、ビルドを実行していないことを簡潔に伝える。

ユーザーが明示的にビルドやPDF生成を依頼した場合に限り、`jarticle` に対応する環境（例：pLaTeXとdvipdfmx）でビルドする。環境がない場合は冒頭設定を勝手に変更せず、未コンパイルであることを報告する。
