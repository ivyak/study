# 書籍ビューアの連続撮影

書籍のページを右矢印キーで送りながら撮影します。Chromeでは、開始時に選んだタブをバックグラウンドで撮影できます。

保存先フォルダは、最初のページの表示が安定し、PNGを保存する直前に作成します。

## Chromeのタブをバックグラウンドで撮影

Chrome 144 以上と Node.js 22 以上が必要です。PDF出力には下記と同じ Python 環境を使います。

1. Chromeで `chrome://inspect/#remote-debugging` を開き、リモートデバッグを有効にします。
2. 書籍の最初のページを1ページ表示にします。目次パネルを閉じ、左右に灰色の余白が見えるようにします。右矢印キーでページを送れる状態にして、最初のページに戻します。
3. リポジトリのルートから次のコマンドを実行します。Chromeに接続許可が出たら許可します。ターミナルにはウィンドウごとにタブのタイトルとURL全体が表示されます。書籍のタブの番号を入力して Enter を押します。

```bash
.venv/bin/python utils/screenshot/book_screenshot.py chrome ~/Downloads/feedback-control-test --max-pages 3
```

撮影が始まったら、別のアプリやChromeの別のタブを使えます。撮影対象のタブは開いたままにし、表示倍率とウィンドウのサイズを固定します。60秒以内に次のページを確認できなければ、その時点までをPDFにします。全ページを撮る場合は `--max-pages 3` を外し、新しい保存先を指定します。

タブのURLが分かっていれば `--tab 'URL'` でも指定できます。手動で起動したChromeに接続する場合は `--debug-port` にローカルのポートを指定します。座標を `--crop` で指定する場合は、Chromeのタブ内の画像の左上を原点にします。

### 複数の区間を同時に撮影

同じ本を同時に開ける場合は、タブごとに撮影する区間の先頭ページを表示します。たとえば各区間25枚なら、最初のタブを1枚目、次のタブを26枚目、その次を51枚目に合わせます。表紙や白紙も撮影枚数に含みます。

```bash
.venv/bin/python utils/screenshot/book_screenshot.py chrome ~/Downloads/feedback-control-batch --parallel 10 --max-pages 25
```

一覧の番号を、本のページ順にカンマ区切りで入力します。たとえば最後だけ17枚なら、最後の番号を `12:17` のように入力します。全タブに個別の枚数を指定する場合は `--max-pages` を省略できます。各タブの最初の表示から指定枚数を数えます。

撮影済みの画像は区間ごとの `part-01/pages/` などに保存します。すべての区間が指定枚数に達すると、入力順で `pages/` にまとめて章別PDFを作成します。途中で止まった区間があれば、区間ごとの画像を残します。タブ同士で閲覧セッションが共有されているサイトでは、並列でも同じ時刻に止まることがあります。

## macOSの画面全体から撮影

### 準備

- macOS 13 以上、Python 3.9 以上、Xcode Command Line Tools、Pillow 9.1 以上、img2pdf が必要です。このリポジトリの `.venv` に Pillow と img2pdf が入っている場合は、そのまま使えます。
- システム設定の「プライバシーとセキュリティ」で「デバイスの制御とデータへのアクセス」を開き、実行元のターミナルアプリを許可します。この項目がない場合は、同じ画面の「アクセシビリティ」を開きます。Ghosttyで実行する場合はGhosttyを許可します。
- 「画面収録とシステムオーディオ録音」でも、実行元のターミナルアプリを許可します。許可が反映されない場合は、ターミナルアプリを終了して開き直します。
- ブラウザをメインディスプレイで広げ、書籍の最初のページを1ページ表示にします。目次パネルを閉じ、左右に灰色の余白が見えるようにします。ビューアをクリックし、右矢印キーでページを送れることを確認します。

### 撮影

リポジトリのルートから実行します。保存先には新しいフォルダを指定します。

```bash
.venv/bin/python utils/screenshot/book_screenshot.py capture ~/Downloads/feedback-control
```

指定した保存先にファイルやフォルダがある場合は、上書きを防ぐため撮影を始めず、まだ使われていない保存先の例を表示します。

撮影開始までの秒数が表示されたら、10秒以内にブラウザを前面にします。撮影中はブラウザを前面にし、表示倍率とウィンドウの位置を固定します。撮影したページは `pages/` に連番のPNGで、章ごとのPDFは `pdf/` に保存します。

ターミナルには準備状況、撮影開始までの秒数、ページの保存、章の読み取りとPDFの作成状況が表示されます。ページの表示を待っている間は、約5秒ごとに経過時間を表示します。

右矢印キーを1回送るたびに、ページ内の画像が前のページと異なり、2秒間変化しなくなるまで待ちます。安定するまでの秒数は `--stable 4` のように変えられます。最終ページや読み込みの停止などで60秒以内に新しいページを確認できない場合は、そこまでの画像をPDFにします。完全に単色の画面や、前のページと同じ表示は画像だけでは区別できません。

最初の3枚だけを試すには `--max-pages 3` を追加します。自動で余白を検出できない場合は、画面全体のスクショを基準に、左・上・右・下の座標をピクセルで指定します。たとえば `--crop 903 108 2133 1894` です。撮影を手動で中断する場合は、ターミナルに戻って Ctrl+C を押します。

### Swiftの補助プログラムが担当する処理

1. `capture` は起動直後にmacOSへアクセシビリティの許可を問い合わせます。許可がなければ、コンパイル、保存先の作成、カウントダウンに進む前に停止します。
2. 許可を確認した後、`swiftc` で `book_screenshot_macos.swift` をコンパイルします。実行ファイルとコンパイル時のキャッシュは一時フォルダに作り、ツールの終了時に片付けます。
3. カウントダウン後、補助プログラムがAppKitを使って前面のアプリのプロセスIDを取得します。ページ送りのときは前面のアプリが撮影開始時と同じか確認し、Core Graphicsを使ってそのアプリに右矢印キーの押下と解放を送ります。画像はmacOS標準の `screencapture` で取得し、Pythonが切り抜きと保存を行います。
4. 章の区切りを自動で判定するときは、補助プログラムがmacOSのVisionを使い、保存済みのPNGの紙面全体から文字と位置を読み取ります。Pythonがその情報から章の区切りを決め、PDFを書き出します。

## 章の区切り

撮影後に紙面全体を文字認識します。目次の見出し、点線、右端に並ぶページ番号から目次の続きも判別します。章扉は、文字の大きさ、題名の配置、最初の節番号を見て探します。章の区切りが見つからなければ、撮影分を1冊のPDFにまとめます。

章の開始位置が分かっている場合は、`capture` のときに `--chapter` を章ごとに指定できます。撮影済みの画像から作り直すときも同じ指定が使えます。番号はPNGの撮影順で、表紙と白紙も数えます。

```bash
.venv/bin/python utils/screenshot/book_screenshot.py pdf ~/Downloads/feedback-control \
  --chapter '8:第1章 序論' --chapter '19:第2章 ダイナミカルシステムの表現'
```

数字は入力例です。章が始まるPNGの番号に置き換えます。最初の章より前の画像は表紙・前付けとして1つのPDFにまとめます。再出力時は、既存のPDFを残して `pdf-2/` などの新しいフォルダに保存します。
