## 1.4 入力の受け取り方 6 パターン（これは丸暗記）

AtCoder の問題は**標準入力**でデータが来て、**標準出力**に答えを書きます。
入力の形は数パターンしかないので、**この 6 つを暗記してください**。毎回ここで手が止まると
それだけで数分溶けます。

### 先に：6 つの違いは「軸 2 本」しかない

6 つもあると別物に見えますが、変わっているのは次の 2 点だけです。

縦が「何行つづくか」、横が「1 行に何個のっているか」です。
**パターン 3 だけが別枠**で、「数列が 1 行にぜんぶ並んでいる」形にあたります。

| | 1 行に 1 個 | 1 行に 2 個以上 |
|---|---|---|
| **1 行で終わり** | パターン 1 `int(input())` | パターン 2 `map(int, input().split())` |
| **数が横に並ぶ** | — | **パターン 3** `list(map(int, input().split()))` |
| **N 行くり返す** | パターン 4 `[int(input()) for _ in range(N)]` | パターン 5 `[tuple(map(...)) for _ in range(N)]` |
| **N 行くり返す（文字列）** | パターン 6 `[input() for _ in range(H)]` | — |

**パターン 2 と 3 は同じ `input().split()` です。** 違いは受け取り方だけで、
個数が決まっている（2 個）なら `A, B =` で展開、個数が可変なら `list()` に入れる。
**パターン 4・5・6 は「1 行ぶんの読み方を N 回くり返しているだけ」**で、
`for _ in range(N)` の中身がパターン 1 / 2 / 文字列に置き換わっているだけです。

### パターン 1: 数値が 1 個

```
入力例
5
```

```python
N = int(input())
print(N * 2)
```

`input()` は 1 行を**文字列として**読みます。`"5"` のままでは足し算できないので
`int()` で数値にします。ここを忘れると `"5" * 2` が `"55"` になって WA します。

### パターン 2: 数値が 1 行に複数（スペース区切り）

```
入力例
3 7
```

```python
A, B = map(int, input().split())
print(A + B)
```

`input().split()` で `["3", "7"]` になり、`map(int, ...)` が各要素に `int()` をかけます。`map` の
結果は**リストではなくイテレータ**ですが、左辺に `A, B` と並べれば展開されます。

### パターン 3: 数列が 1 行

```
入力例
5
1 2 3 4 5
```

```python
N = int(input())
A = list(map(int, input().split()))
print(sum(A))
```

`list(...)` を付けるのを忘れないこと。`map` のままだと `A[0]` のような添字アクセスも `len(A)` も
できず、**一度使うと中身が消える**（イテレータなので）のも事故のもとです。

> **「`N` を読んだのに使っていないのでは？」** と思ったら、そのとおりです。
> ここには理由があります。**[§1.5](#15-なぜパターン-3-は-n-を使っていないのか)** で説明します。

### パターン 4: N 行にわたって数値が来る

```
入力例
3
10
20
30
```

```python
N = int(input())
A = [int(input()) for _ in range(N)]
print(max(A))
```

`_` は「使わない変数」という意味の慣習的な名前です。`for i in range(N)` でも動きます。

### パターン 5: N 行にわたってペアが来る

```
入力例
3
1 2
3 4
5 6
```

```python
N = int(input())
AB = [tuple(map(int, input().split())) for _ in range(N)]
for a, b in AB:
    print(a + b)
```

グラフの辺（§6）がこの形で来ます。「N 行、それぞれに 2 つの数」は最頻出です。

#### なぜ `list` ではなく `tuple` なのか

**どちらでも動きます。** `for a, b in AB` のアンパックも `sorted(AB)` の結果も、
list と tuple で変わりません。それでも `tuple` を既定にするのは、次の差があるからです。

| | `tuple(...)` | `list(...)` |
|---|---|---|
| 表している意味 | **個数が固定の「組」**（2 個で 1 セット） | **個数が可変の「並び」** |
| `set` に入れる／`dict` のキーにする | **できる** | **できない**（`TypeError: unhashable type: 'list'`） |
| 中身の書き換え | できない（うっかり壊すのを型が止める） | できる |
| メモリ（2 要素） | 56 バイト | 72 バイト |

**2 行目が実戦で効きます。** 「訪問済みの座標」「使った辺」を集合で持つのは頻出で、
tuple はそのまま入りますが、list は入りません（§6.5 のグリッド探索で使います）。

```python
seen = set()
seen.add((i, j))     # ○ tuple はそのまま set に入る
seen.add([i, j])     # ✗ TypeError: unhashable type: 'list'
```

逆に、**あとで中身を書き換えるなら `list`** にしてください（辺の重みを更新する等）。
生成の速さは実測でほぼ同じなので、速度を判断材料にする必要はありません。

### パターン 6: 文字列のグリッド（H 行 W 列）

```
入力例
3 4
....
.#..
...#
```

```python
H, W = map(int, input().split())
S = [input() for _ in range(H)]
print(S[1][1])   # 2 行目の 2 文字目 → '#'
```

迷路やマス目の問題（§6.5）はこの形です。`S[i][j]` で i 行目 j 列目の 1 文字が取れます。
**`S` はリストの中に文字列が入っているだけ**なので、書き換えたいときは
`S = [list(input()) for _ in range(H)]` と**文字のリストのリスト**にします（文字列は書き換え不可）。

## 1.5 なぜパターン 3 は `N` を使っていないのか

パターン 3 をもう一度見ます。

```python
N = int(input())
A = list(map(int, input().split()))
print(sum(A))
```

`N` を読んでいるのに、そのあと一度も出てきません。パターン 4・5 が
`for _ in range(N)` で堂々と `N` を使っているのと対照的です。理由は 2 つあります。

### 理由 1: `N` を読まないと、次の行が読めない

**`input()` は「次の 1 行を消費する」関数**です。入力はこうなっています。

```
   1 行目:  5              ← ここを読み飛ばさないと
   2 行目:  1 2 3 4 5      ← ここにたどり着けない
```

もし `N = int(input())` を書かずに いきなり `A = list(map(int, input().split()))` と書くと、
**1 行目の `5` を数列として読んでしまい**、`A` が `[5]` になります。

つまり `N = int(input())` は、値が要るから書いているというより
**「1 行目を消費するために書いている」**面があります。実際、次のように書いても動きます。

```python
input()                                     # 1 行目を読み捨てるだけ
A = list(map(int, input().split()))
print(sum(A))
```

ただし**この書き方はおすすめしません**。あとで「やっぱり N が要る」となったとき書き足す手間が
かかり、読み手（＝提出後の自分）に意図も伝わりません。
**受け取るのはタダなので、素直に `N = int(input())` と書くのが定石**です。

### 理由 2: パターン 3 は `N` が無くても長さが分かる

`split()` は「その行にあるものを全部」分けるので、**`A` の長さは自動的に N になります**。
だから長さが必要なら `len(A)` で取れます。一方、パターン 4・5 は

```
   3        ← この N を読まないと、
   10       ← 何行読めばいいのか分からない
   20
   30
```

**「あと何行読むか」が N でしか決まりません**。だから `range(N)` で明示的に使います。
これが「パターン 3 だけ N が出てこない」ことの正体です。

```
   N の役割の違い

   パターン 3 : N は「1 行目を消費する」ため。長さは split() が勝手に決めてくれる
   パターン 4 : N は「何回 input() を呼ぶか」を決める。無いと読む量が分からない
   パターン 5 : 同上
   パターン 6 : H が「何行読むか」、W は使わないことも多い（len(S[0]) で取れるため）
```

パターン 6 で `W` を使っていないのも同じ理由です。`H` は行数を決めるのに必要ですが、
`W` は文字列の長さとして自動的に決まります。

### 検算のクセをつけると安全

読み込みが合っているか不安なときは、**読んだ直後に長さを確認する**のが早いです。

```python
N = int(input())
A = list(map(int, input().split()))
assert len(A) == N          # 提出前に消す（残っていても AC には影響しないが、念のため）
```

`assert` は条件が偽のとき例外を投げます。読み方を間違えていれば手元で止まるので、
「なぜか答えが合わない」を早い段階でつぶせます。

## 理解度チェック

<details>
<summary><b>Q1.</b> パターン 3 で `N = int(input())` を消すと何が起きる？ `N` は使っていないのに。</summary>

**A.** **1 行目の `5` が数列として読まれてしまい、`A` が `[5]` になる。**
`input()` は「次の 1 行を消費する」関数なので、1 行目を読み飛ばさないと 2 行目にたどり着けない。
`N` は値として使わなくても、**行を消費する役目**を持っている。
`input()` とだけ書いて読み捨てても動くが、意図が伝わらないので素直に受け取るのが定石。→ §1.5
</details>

<details>
<summary><b>Q2.</b> パターン 6 で `W` を読んでいるのに使っていない。消してよい？</summary>

**A.** **消してはいけない。** `H, W = map(int, input().split())` は 1 行を丸ごと読んでいるので、
`W` の受け取りをやめても行の消費は変わらないが、`H` と一緒でないと書けない。
使わないのは「行の長さは `len(S[0])` で分かるから」であって、読む必要が無いわけではない。
パターン 3 の `N` と同じく、**読むこと自体に意味がある**。→ §1.5
</details>

<details>
<summary><b>Q3.</b> `A = map(int, input().split())` と書いて `len(A)` でエラーになった。なぜ？</summary>

**A.** `map` が返すのは**リストではなくイテレータ**で、長さを持たず、
一度なめると中身が尽きる。数列として持ち回るなら `list(map(int, ...))` と
必ず `list` で包む。`A, B = map(...)` のようにその場で展開するときだけ `list` は不要。→ §1.4
</details>
