# 教材データ

実例は `apps/recall-quiz/decks/calc2-lesson01.json`。JSONのインデントはスペース2つ。

| フィールド | 内容 |
|---|---|
| `schemaVersion` | 1。アプリのデータ形式。 |
| `id` | 英小文字・数字・ハイフンによる固定のデッキID。 |
| `version` | 1以上の整数。教材更新で増加させる。 |
| `title`、`subtitle`、`scope` | 科目名、授業回、今回の出題範囲と未対象範囲。 |
| `sourceManifest` | 原資料ごとのリポジトリ相対パス `file`、`sha256`、`pageCount`、照合済みの `reviewedPages`、照合方法 `method`。 |
| `questions` | 次の問題オブジェクトの配列。 |

問題は `id`、`version`、`prompt`、`answer`、`criterion`、`explanation`、`sources` を持つ。

- `id` は科目・授業回を含め、他デッキとも衝突しない固定IDにする。
- `prompt` は問い、`answer` は短い答え、`criterion` は自己判定基準。`explanation` は任意の補足文で、不要な場合も空文字を入れる。
- 数式の区切りは `\( ... \)`。JSONに書くときは `"\\( ... \\)"` のようにバックスラッシュを二重にする。任意のHTMLは書かない。
- `sources` は `file` にPDFのファイル名、`page` に1始まりの物理ページ番号を持つ配列。`sourceManifest` のファイル名と照合する。印刷上のページ番号と違う場合は補足に明記する。
- `promptHtml` などの表示用フィールド、`renderVersion`、原典画像の `sourceImages` と各参照の `imageKey` はビルドが生成する。手で書かない。画像はPDFの同じページを1回だけ埋め込み、複数問題から共有する。iPhoneの教材読み込みでは生成済みの `.compiled.json` を使う。

学習記録は教材と別の `state.json` に保存される。回答イベントに問題IDと問題版を残し、古い版への回答も消さない。問題を変更して版を増やすと、その問題は新しく確認する候補に戻る。


## 簿記の解答

仕訳・勘定口座・表が解答になる場合は、通常の `answer` を残し、任意項目 `answerBlocks` に表示用の構造を指定する。`answerBlocks` は1個以上のオブジェクトの配列とする。任意のHTMLを直接書くのではなく、ビルドがこのデータからHTMLの表を生成する。出題画面、一覧、履歴で同じ解答を表示する。

仕訳は借方を左、貸方を右に置き、それぞれ勘定科目と金額の2列にする。勘定科目は括弧付きで表示する。金額が未指定なら `***` を使い、金額の意味は `note` で補う。指定金額を `***` に置き換えたり、未知の金額に0や架空の数値を入れたりしない。仕訳が複数ある場合はブロックを分ける。

```json
"answerBlocks": [
  {
    "type": "journal",
    "caption": "賃金給料の支払い",
    "debit": [{ "account": "賃金給料", "amount": "***" }],
    "credit": [
      { "account": "預り金", "amount": "***" },
      { "account": "現金", "amount": "***" }
    ],
    "note": "賃金給料は控除前の総額。預り金は控除額、現金は差引支払額。"
  }
]
```

- `journal` は仕訳。`debit` と `credit` はそれぞれ借方・貸方で、どちらにも1行以上の科目と金額を入れる。金額は文字列で指定する。
- `ledger` はT字型の勘定口座。`caption` に勘定名を書き、`debit` と `credit` は上の仕訳と同じ形で指定する。記入がない側は空配列にする。科目欄には相手科目、必要に応じて繰越項目などを入れる。勘定名の括弧は付けない。
- `table` は原価計算表などの表。`headers` に列見出しの文字列配列、`rows` に同じ列数の文字列配列を並べる。任意の `totalRows` に、合計行の0始まりの行番号を指定できる。
- `caption` は表題、`note` は表の下の補足文。`ledger` の勘定名を除き、省略できる。

表の例は次のとおり。

```json
{
  "type": "table",
  "caption": "完成品の原価計算表",
  "headers": ["摘要", "金額"],
  "rows": [
    ["直接材料費", "***"],
    ["直接労務費", "***"],
    ["直接経費", "***"],
    ["製造間接費の配賦額", "***"],
    ["完成品原価", "合計"]
  ],
  "totalRows": [4]
}
```

表の数値、左右、合計行、単位を原資料と照らし合わせ、文章の `answer` と食い違わないようにする。表示形式だけを整え、問い・答えの意味・判定基準を変えない場合は、問題IDと問題の `version` を維持し、デッキの `version` を更新する。スマホ幅で借方と貸方が区別できること、列や金額が重ならないことも確認する。
