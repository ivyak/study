# 数理工学実験のレポートひな形を作る

指定された実験テーマ**一つ**のLaTeXひな形を作る。原典は `Kyoto_Univ/[2026後期月３]数理工学実験/授業資料/数理工学実験2026.pdf` と `Kyoto_Univ/[2026後期月３]数理工学実験/授業資料/数理工学実験ガイダンス資料2026.pdf`。テーマ1〜7は教材の第2〜8章に対応する。テーマと教材の章番号を確認し、曖昧なら資料に基づいて特定する。既存の `LaTeX_website/sample.tex` は組版の参考例であり、問題や提出要件の原典ではない。

対象章を全ページ読み、本文中・章末の実験課題、全設問、小問、条件、表、式を洗い出す。PDF抽出は日本語や数式を壊すことがあるため、問題文は必ずページ画像と照合して転記する。問題番号と原典のPDFページを各設問に残し、印刷ページ番号が異なる場合は併記する。任意・発展課題は明確に区別する。読めない文字や図を推測で確定しない。転記不能な箇所は原典位置と未確認の内容を目立つTODOで示し、完成した転記と呼ばない。

## ひな形の内容

- 編集できる `.tex` をユーザー指定先、指定がなければ科目フォルダ内のテーマ別フォルダに保存する。既存の完成原稿を上書きしない。利用可能なLaTeX環境と既存スタイルに合わせ、可能ならコンパイルできる状態にする。
- 表紙には科目、テーマ、実験日、提出日、提出先、氏名、学籍番号の記入欄を用意する。要約、課題・手法、実験条件とコード、結果、考察、結論、参考文献、AI利用の記載欄を設ける。章立てはテーマの問題構造に合わせ、空の見出しを無意味に増やさない。
- **各設問の問題文を明記**し、対応する解答欄を設ける。解答欄には、本人が記すべき情報を短いTODOで示す。手法・アルゴリズム、コードまたは提出ファイル名、入力・パラメータ、結果、図表、理論値との比較、誤差・単位、考察を、その設問が要求する範囲で分かるようにする。コードを掲載できる環境または外部コードファイルを取り込む欄を設け、言語をCに固定しない。図表の番号、キャプション、本文参照の書き方を、実データを捏造しない形で示す。
- 解法、完成コード、計算済みの数値、考察文は埋めない。教材に載る既知の定義・問題条件と、学生が検証すべき成果を区別する。空欄を他人がそのまま提出できる完成レポートのように見せない。
- 参考文献欄には実際に参照した教材等を特定できる枠を設ける。生成AIによるひな形作成は利用事実として扱い、AIのツール名・用途・影響した箇所・本人による確認を書ける欄を置く。使っていない用途を自動で宣言しない。ユーザーに自身のAI利用と確認作業を追記させる。

## 提出条件と学習目的

ガイダンス p.2–3 では、LaTeXは強く推奨されるが必須とはされていない。今回は依頼に従いLaTeXを作る。テーマごとにKULMSへ提出し、期限は担当教員の指示に従う。レポートに使った動作するコード等も提出対象である。コード・レポート作成に生成AIを使った場合は適切に引用する。本人が教材を理解し、試行錯誤して実験し、結果を説明することが授業の目的なので、その作業を代行する内容をひな形に含めない。

依頼者が重視する書法も反映する。感想文ではなく客観的事実を伝える構成にし、事実と考察を分ける。最初に目的と成果を要約でき、方法・結果・考察・結論を追えるようにする。物理量・記号の意味や単位、条件を本人が定義する欄を置く。図表は番号・キャプション・本文からの参照を前提にする。引用は可能なら確認した原典を示し、Webのみなら出典と閲覧日を記す。曖昧な文章や未確認の理論値をひな形側で書き込まない。

完成後、全設問と `.tex` の対応を確認し、転記に不確かな箇所、未記入欄、ビルド結果、使用方法を短く報告する。ひな形は未完成のレポートであることを明示する。
