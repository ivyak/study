## 2.1 問題文の「制約」は、答えのヒントである

AtCoder の問題文には必ず **制約** という欄があります。

```
制約
・1 ≤ N ≤ 200000
・1 ≤ A_i ≤ 10^9
```

開発の感覚だと、ここは「まあ常識的な範囲だろう」と読み飛ばす場所です。競プロでは逆で、
**ここが問題文の中でいちばん情報量が多い**。出題者は、

> 「素直な方法（二重ループ）では絶対に間に合わない大きさ」

を狙って N の上限を決めています。つまり **N の上限を見た瞬間に、使ってよい解法が絞れる**。

```mermaid
flowchart LR
    A["制約 N ≤ 200000 を読む"] --> B["O(N^2) は 4×10^10 回。<br/>絶対に無理と判定"]
    B --> C["O(N log N) までに<br/>収める必要がある"]
    C --> D["ソート？ 二分探索？<br/>累積和？ と候補が出る"]
```

**書き始める前にこの矢印をたどる。** これができるかどうかが C の壁です。

## 2.2 O 記法 — 「N が増えたとき、何回に増えるか」

計算量（オーダー）は `O(N)` `O(N²)` `O(N log N)` のように書きます。意味は
**「入力サイズ N に対して、処理が何回くらい行われるか」**です。定数倍や細かい項は捨てます。

```python
# O(N) : N 回
for i in range(N):
    ...

# O(N^2) : N × N 回
for i in range(N):
    for j in range(N):
        ...

# O(N^3) : 三重ループ
for i in range(N):
    for j in range(N):
        for k in range(N):
            ...

# O(log N) : 半分ずつ減らしていく（二分探索）
while lo < hi:
    mid = (lo + hi) // 2
    ...
```

数字を入れると、差がどれくらい暴力的かが分かります。

| N | O(log N) | O(N) | O(N log N) | O(N²) | O(2^N) |
|---|---|---|---|---|---|
| 10 | 3 | 10 | 33 | 100 | 1,024 |
| 1,000 | 10 | 1,000 | 10,000 | 1,000,000 | 桁が大きすぎ |
| 100,000 | 17 | 100,000 | 1,700,000 | **10,000,000,000** | — |
| 1,000,000 | 20 | 1,000,000 | 20,000,000 | **10^12** | — |

N = 100,000 のとき、`O(N)` は 10 万回で一瞬。`O(N²)` は **100 億回**で、どう頑張っても 2 秒に入りません。
**「ちょっと遅い」ではなく「絶対に無理」**という差です。ここが実感として腹に落ちるまでが勝負です。

## 2.3 2 秒で何回まわせるか（Python の現実的な目安）

AtCoder の実行時間制限は通常 **2 秒**です。言語によって「2 秒で回せる回数」が全然違います。

| 言語 | 2 秒で安全に回せる回数の目安 |
|---|---|
| C++ | 10^8 〜 10^9 |
| **Python (PyPy)** | **10^7 〜 10^8** |
| **Python (CPython)** | **10^6 〜 10^7** |

これは**厳密な数字ではなく、ループの中で何をしているかで数倍変わります**。
それでも「CPython の素のループは 1 秒におよそ 10^7 回」という感覚は持っておいてください。

> **競プロ記事の目安は C++ 基準で書かれていることが多い**（「10^8 までなら間に合う」など）。
> Python はそこから **1 桁引く**、と覚えると事故が減ります。

```
   C++      ████████████████████  10^8〜10^9
   PyPy     ████████████          10^7〜10^8      ← ここを基準にする
   CPython  ██████                10^6〜10^7
```

## 2.4 【最重要】制約 → 解法の逆算表

**この表を暗記してください。** N の上限を見たら、この表で解法の候補を引きます。

| N の上限 | 許される計算量 | 典型的な解法 |
|---|---|---|
| N ≤ 10 | O(N!) ＝ 順列全探索 | `itertools.permutations` で全部試す |
| N ≤ 20 〜 25 | O(2^N) ＝ bit 全探索 | 各要素を「選ぶ / 選ばない」で全部試す → [§3.4 bit 全探索](./01_3_AB問題_全探索の型.md) |
| N ≤ 100 | O(N³) | 三重ループ、ワーシャルフロイド |
| N ≤ 2,000 | O(N²) | 二重ループ、区間 DP → [§5.5 区間 DP・bit DP](./01_5_D問題その1_DP.md) |
| N ≤ 10^5 〜 2×10^5 | **O(N log N)** | **ソート、二分探索、優先度付きキュー** → [§4-1 累積和・ソート・貪欲](./01_4_1_C問題_累積和とソートと貪欲.md) [§4-2 二分探索・しゃくとり・数え上げ](./01_4_2_C問題_二分探索としゃくとりと数え上げ.md) |
| N ≤ 10^6 | O(N) | 累積和、しゃくとり法、1 回なめるだけ |
| N ≤ 10^9 | O(√N) か O(log N) | 約数列挙、答えを二分探索、数式で解く → [§7.1 約数列挙](./01_7_D問題その3_数学_約数と素数とmod.md) |
| N ≤ 10^18 | O(log N) | 繰り返し二乗法、数式。**ループを 1 回も回さない** |

使い方の例を 2 つ。

### 例 1: `N ≤ 2×10^5` と書いてある

二重ループは 4×10^10 回。**即座に却下**。ソート（O(N log N)）は 2×10^5 × 18 ≒ 360 万回で余裕。
→ 「ソートして何かする問題」「二分探索する問題」「累積和で前処理する問題」を疑う。

### 例 2: `N ≤ 20` と書いてある

不自然に小さい。O(N²) なら 400 回で、こんな制約を置く理由がない。
**20 という数字は 2^20 ≒ 100 万を意識した数字**です。→ **bit 全探索**を疑う（§3.4）。

> **制約が不自然に小さいときは、指数時間の解法を要求されているサイン。**
> N ≤ 10 なら順列全探索、N ≤ 20 なら bit 全探索。

## 2.5 変数が 2 つあるときは掛ける

制約が `N ≤ 1000, M ≤ 1000` のように 2 つあるとき、計算量は `O(NM)` になりがちです。

```python
for i in range(N):        # N 回
    for j in range(M):    # その中で M 回
        ...               # 合計 N × M 回
```

`1000 × 1000 = 10^6` なので Python でもぎりぎり通ります。ただし
`N ≤ 10^5, M ≤ 10^5` なら `10^10` で無理。**「2 つ出てきたら掛ける」を機械的にやってください。**

グラフの問題では頂点数 `N` と辺数 `M` が出てきます。BFS は `O(N + M)`（掛け算ではなく足し算）で、
これが「グラフ探索が速い」と言われる理由です（§6）。

## 2.6 計算量に入らないもの、入るもの（Python 特有の落とし穴）

Python は「1 行で書けること」が多いぶん、**書いた行数と計算量が一致しません**。
以下は全部 O(N) 以上かかる操作です。見た目が短くても中でループが回っています。

| 書き方 | 計算量 | 注意 |
|---|---|---|
| `x in A`（A がリスト） | **O(N)** | ループの中で使うと O(N²) になる。`set` にすれば O(1) |
| `A.index(x)` | O(N) | 同上 |
| `A.remove(x)` / `del A[0]` / `A.pop(0)` | **O(N)** | 先頭の出し入れは `collections.deque` を使う |
| `A.insert(0, x)` | O(N) | 同上 |
| `s += "a"` を N 回（文字列） | **O(N²)** | 文字列は毎回作り直される。`''.join` を使う |
| `max(A)` / `sum(A)` / `min(A)` | O(N) | ループの中で呼ぶと O(N²) |
| `sorted(A)` / `A.sort()` | O(N log N) | ループの中で呼ぶと O(N² log N) |
| `A[i]`（添字アクセス） | O(1) | これは速い |
| `x in S`（S が `set` / `dict`） | **O(1)** | 存在判定はこれ |

**いちばんよくある事故がこれです。**

```python
# ✗ O(N × M)。N も M も 10^5 なら 10^10 回で TLE
for x in B:
    if x in A:      # A がリストなら、ここで毎回 A を全部なめている
        ...

# ○ O(N + M)。set にするだけで劇的に速くなる
SA = set(A)
for x in B:
    if x in SA:     # O(1)
        ...
```

`set` は内部でハッシュを使っていて、「入っているか」を一発で判定できます。
**リストに対する `in` を見たら反射的に疑ってください。**

## 2.7 見積もりの手順（毎回これをやる）

```
1. 制約の N の上限を読む
2. §2.4 の表で、許される計算量を引く
3. 思いついた解法のループ回数を数える
4. 3 が 2 を超えていたら、書き始めない。別の解法を考える
```

ステップ 4 が本当に大事です。「とりあえず書いてみて、TLE したら考える」をやると、
**書く 10 分＋TLE を見る 1 分＋直す 10 分**が溶けます。書く前に 30 秒で判定してください。

### 「思いつかない」ときの逃げ道

見積もりの結果、必要な計算量が分かっているのに解法が出てこない場合。

- **O(N log N) が必要** → ソートしてみる。二分探索できないか考える（§4）
- **O(N) が必要** → 累積和、しゃくとり法、1 パスで持ち回れる情報は何か（§4）
- **O(√N) が必要** → 約数、素因数分解（§7）
- **N が小さい（≤ 20）** → 全部試す（§3）

この 4 本しか道がないので、**外れたら次を試す**という進め方ができます。

## 理解度チェック

<details>
<summary><b>Q1.</b> 制約が `2 ≤ N ≤ 200000` の問題で、二重ループの解法を思いついた。書いてよい？</summary>

**A.** 書いてはいけない。2×10^5 の二乗は **4×10^10 回**で、Python どころか C++ でも間に合わない。
必要なのは O(N log N) 以下。ソート・二分探索・累積和のどれかを疑う。
**書く前に 30 秒でこの判定をする**のが C を取るための手順。→ §2.4 / §2.7
</details>

<details>
<summary><b>Q2.</b> 制約が `N ≤ 18` だった。この不自然に小さい数字は何のサイン？</summary>

**A.** **bit 全探索**（O(2^N)）のサイン。2^18 ≒ 26 万回で、全部試せる大きさ。
O(N²) なら 324 回しかなく、こんな上限を置く意味がない。
「N ≤ 10 なら順列全探索、N ≤ 20〜25 なら bit 全探索」と覚える。→ §2.4 / §3.4
</details>

<details>
<summary><b>Q3.</b> 次のコードは N = 10^5 で TLE する。どこが重い？ 1 行で直せる。</summary>

```python
A = list(map(int, input().split()))
B = list(map(int, input().split()))
cnt = 0
for x in B:
    if x in A:
        cnt += 1
print(cnt)
```

**A.** `x in A` が **A に対する線形探索 O(N)**。それを B の要素ぶん繰り返すので O(N×M) ＝ 10^10。
ループの前に `A = set(A)` を入れれば `in` が O(1) になり、全体 O(N+M) で通る。
**リストへの `in` はループの中で使わない**。→ §2.6
</details>
