# 講義スライド解説

スライドを見ながら読む補助文章を作る。原文の言い換えではなく、「何を意味し、なぜそうなり、問題でどう使うか」を短時間で理解できる解説にする。理系に限らず講義固有の定義・記法・条件を尊重する。

## 入力と保存

対象PDF、科目、資料一覧、先行する解説、利用可能な過去問・演習・課題を確認する。不足資料があっても確認できた範囲で進める。

このリポジトリでは読者向けの解説をLIFEの科目ページとして提供する。構成とUIは `Kyoto_Univ/ui/mock.html` を規範として厳格に踏襲する。ページ上部に開閉式の「目次」を置き、その後に「講義を通して言いたいこと」、章見出し、各スライドの「解説」と対応する原スライド画像を見本と同じ配置で続ける。見本と異なる独自レイアウト、独自ナビゲーション、画像の代わりのプレースホルダーを作らない。

ページは科目フォルダ直下に置く。横のナビゲーションはポータルと同じ `Kyoto_Univ/ui/shell.html` を唯一の元にする。科目ページの `<div class="shell">` と `<main>` の間を `<!-- LIFE-SHELL:START -->` / `<!-- LIFE-SHELL:END -->` で囲み、`Kyoto_Univ/update_portal.py` で共通シェルを同期する。既存の科目ページからサイドバーのHTMLをコピーして固定しない。パンくず、戻り導線、数式表示の設定は `Kyoto_Univ/[2026後期木３]微分積分学続論II/第2回_同次形・完全形と線積分.html` の構成に合わせ、共有の `Kyoto_Univ/ui/life.css` と `life.js` を使う。`mock.html` の本文構成をその共通シェル内に実装する。授業回のページ一覧に載るよう `study-lesson`、`study-kind`、`study-created` メタデータを設定し、`Kyoto_Univ/update_portal.py` を実行してポータルを更新する。

他の環境ではLIFE固有のHTMLやメタデータを必須にせず、ユーザー指定の形式と既存構成を優先する。

出力形式・保存先の指定と既存構成を優先する。このリポジトリで指定がなければ、読者向け本文を科目フォルダ直下の「第N回_資料名.html」として作り、ポータルから該当授業回の「解説」で開けるようにする。`study/slide-explanations/course-context.md` には資料判定・根拠・用語の初回説明位置を記録する。管理記録を読者向けページの代わりにしない。授業回が推定または不明ならファイル名やメタデータに事実として書かず、元PDF名を使い、HTMLの見える位置に判定状態を示す。HTMLを使わない環境やユーザーが指定した場合は、その環境に適した形式で保存する。

## 1. 原典と資料の位置を確認する

- 全ページを確認する。テキスト抽出だけで図・数式・段組みを理解できない箇所はページ画像を見る。疑わしいOCR結果は原画像と照合し、読めない情報を推測で埋めない。
- PDFページは1始まりで記録し、印字されたスライド番号と区別する。1ページに複数枚ある場合は個別に解説し、`PDF p.3・左上` など位置も記録する。重複や段階表示も各枚の対応を残す。
- 科目、年度・学期、担当者、授業回、同じ回の何個目の資料かを別々に判定する。章番号・PDFページ・スライド番号と混同しない。
- 根拠はユーザーの示した対応、PDF内の明示、授業の資料一覧・配布順、シラバス・日付、ファイル名、内容の連続性。矛盾は具体的に示し、どの根拠を採用したか残す。内容の類似だけでは確定しない。
- 各項目に `確認済み／推定／不明` と根拠のファイル・ページ等を付ける。PDFが1つだけでも第1資料とは限らない。複数授業回にまたがるPDFは範囲ごとの対応を残す。
- 不明でも本文生成は続ける。読順が不明なら既出用語を説明済みと扱わず、今回必要な説明を補う。

## 2. 要旨と章別目次を先に作る

全体を読んで「この資料を通して言いたいこと」を通常1〜3文で示す。項目の列挙ではなく、到達する理解や使えるようになることを書く。授業の一部を扱う資料なら授業全体の要旨と断定しない。

原典に目次・章見出しがあれば構造と順番に従う。なければ話題・目的の切り替わりで大まかに章分けし、生成した区分と分かるようにする。等間隔のページ分割はしない。

章別目次には章名、スライド範囲、本文へのリンクを付ける。全スライドをいずれかの章に割り当て、元の順番を保つ。表紙・目次・参考文献も個別に対応させ、解説は短い案内にする。

## 3. 過去問・演習から詳しさを調整する

データがあれば問題本文まで確認する。根拠は同じ担当者・科目の過去問、授業の演習・課題、指定教科書の問題、近い科目の類題の順に優先する。年度・担当者・範囲の違いは適合性の限界として記録する。対応問題は年度・ファイル・問題番号で短く参照する。

各内容が問題で直接使われるか、後続の重要事項の前提か、条件を落とすと誤用するかを判断する。

- **重点**：計算・導出・証明が問われる、または問題解決の中核。再現に必要な論理や手順を説明する。
- **標準**：概念、適用条件、重要事項の前提。意味・接続・必要な条件を説明する。
- **概要**：確認した問題との直接の対応がなく、後続の理解・問題解決への寄与も小さい。先へ進むための結論と用途に絞る。

詳細度を下げた箇所は「優先度低・概要でよい」と、その理由を本文に一言添える。「確認した年度では直接の出題なし」と「出題されない」を区別する。未出題だけを理由に必須の前提を削らない。

データがなければ「過去問・演習未確認。詳しさは内容上の必要性で暫定判断」と冒頭に一度書く。各枚で繰り返さない。外部の過去問探索が別途求められた場合は、利用可能なら `kyoto-past-exams` を使う。

証明は、証明自体の出題、解法に転用できる発想、条件や誤用の理解への効果がある場合に必要な部分を詳しくする。それらの効果が小さければ「何を示すか・核となる考え方・結論」の概要にとどめ、長い式変形を再掲しない。同じ証明内でも有用な段階だけ補足してよい。

## 4. 用語と前提を読順で管理する

生成前にその科目の先行する解説と `course-context.md` を確認する。スライドや目次に登場しただけでは説明済みとみなさない。別科目で既知とは自動的に仮定しない。

- その講義のそれ以前の解説で未説明の用語は、最初に使う直前または同じ文で短く説明する。略語・記号も対象。見出しだけに登場する語は最初の本文で説明する。
- 既出なら原則重複説明せず、必要時だけ以前の解説へのリンクと一言の復習を添える。意味・適用条件が変わる場合は差分を説明する。
- 前提知識は今回の理解に必要か、既知と判断する根拠があるかを検討する。不可欠で未説明・理解が不確かなものは最小限補う。周辺知識まで遡る長い入門は作らない。
- 後の章の説明を前提に進めない。必要な定義は初出で補い、詳しい応用を後の章へつなぐ。
- 用語、講義内での意味、初回説明の資料・スライド・アンカー、補った前提を記録する。未確認の解説を説明済みと捏造しない。

追加・削除・移動に応じて記録を更新する。先行資料の変更で後続の参照や前提に影響する場合は依存箇所も確認し、修正範囲を示す。

## 5. スライド1枚ごとに解説を書く

各枚に「この1枚の主張」を短く示し、必要な解説を続ける。章の概説だけで個別解説を代替しない。

- 意味、前の内容とのつながり、式・図の読み方、問題での使い方のうち、その枚の理解に必要なものに絞る。毎回同じ欄を機械的に埋めない。
- 用語補足は自然な位置に挟む。原文のコピーや箇条書きの逐語的な言い換えを避ける。ただし定義名・必要な式・記法・仮定は正確に保持する。
- 数式と数式中の記号はLaTeXで書く。Markdownではインラインに `\( ... \)`、独立した式に `\[ ... \]` を使う。HTMLでは既存レンダラーに合う区切りを使い、式を画像だけにしない。初出記号の意味と必要な条件を説明する。
- 図では軸・矢印・比較・変化の意味を補う。仮定・定義域・単位・例外を短さのために落とさない。原典の誤記らしい箇所は黙って修正せず、原典と補足を区別する。
- 本文は通常1〜3段落を目安にし、難所は必要な長さを使う。文字数を満たすために増やさない。例・比喩は理解を助けるときだけ使う。
- 既述の定義、同じ主張の言い直し、全面的な章末再要約を削る。重複・段階表示の枚は追加された点を中心に短く説明し、説明済みの位置へリンクする。
- 演習スライドは問われる能力と必要な考え方を説明する。解答を求められていなければ完全解答を先に示さない。

## 6. 想定読了時間を示す

各スライド、各章、資料全体に解説の想定読了時間を書く。解説と補足の読解を対象にし、原典の熟読、演習、証明・計算の自力再現は含めない。

日本語本文は毎分400〜600字を暫定目安とし、式や図との照合・推論負荷を加算する。読者の実測があれば調整する。秒単位の精度を装わず「約30秒」「約2〜3分」などと示す。章・全体は未丸めの見積もりを合計してから丸め、全体には要旨・目次も含める。共通補足を何度も加算しない。見積もりの前提は冒頭に一度だけ書く。

## LIFE科目ページの厳守する構成

- `mock.html` と同じ順・配置にする。科目ページのヘッダーとパンくずの後、区切り線を置き、本文を `.reader` の中へ置く。`.reader` は解説本文の `<article>` と、開閉式目次の `<nav class="toc">` で構成する。画面では「目次」ボタンを入口にし、記事内は要旨、章見出し、スライドごとの解説と原スライド画像の組を続ける。
- 目次は `mock.html` と同じ「目次」ボタンと開閉パネルを使う。パネルは「講義の要点」から始め、章の見出しと配下の各スライドへリンクする。目次を固定サイドバーや通常のリンク一覧に置き換えない。
- 解説本文の最初は `<section class="summary" id="summary">`、見出しは「講義を通して言いたいこと」とする。その後、原典の章順に章見出しを置き、各PDFページを一つずつ `<section class="explanation" id="slide-NNN">` として並べる。すべてのPDFページを同じ原順で扱う。
- 各 `.explanation` は `.explanation-grid` を持つ。片側に「解説 N」とそのスライドの主張・要点を置き、もう片側の `.slide` に対応する原スライド画像を置く。残りの詳しい説明は見本どおりグリッドの後に続ける。解説とスライドを別々の全ページ一覧に分離しない。モバイルでは共通UIと同じく縦に並べる。図の意味を説明する場合も、再現図を原スライドとして表示しない。
- PDFページ画像は元PDFの該当ページから生成し、科目内の `assets/` 等に保存する。各画像にページ番号を含む代替テキストを付け、画像または隣接リンクから原PDFの `#page=N` を開けるようにする。1ページに複数スライドがある場合は領域ごとに画像を切り分け、同じPDFページ番号と位置を記録する。
- 横のタブは `ui/shell.html` から同期する。`LIFE-SHELL` マーカーを入れ、ポータルと科目ページで同じ項目・順序・アイコン・選択状態になることを確認する。パンくず、戻りリンク、色・余白・目次の開閉動作は `life.css` / `life.js` と微分積分学続論IIの既存ページに合わせる。数式は同ページのMathJax設定に合わせ、HTML内へ式を画像だけで埋め込まない。
- 共通UIで本文の「未読・勉強中・完了」、第N回一覧では作成日の隣で縦位置をそろえた状態バッジ、時間割の白・青・緑の枠（未読の四角は金色）、小見出しのしおりを表示する。しおりは文字行と高さをそろえた小さな金枠の円とし、選択中は金色で塗る。星や資料HTML独自の操作UIを追加しない。資料固有の `.dot` などが共通UIのクラスと衝突しないよう確認する。
- `<meta name="study-lesson" content="N">`、`<meta name="study-kind" content="解説">`、`<meta name="study-created" content="YYYY-MM-DD">` を記録し、ページのタイトル・見出しに授業回と内容を示す。回が未確定なら授業回のメタデータは付けず、関連資料として登録する。
- HTMLを保存したら `python3 Kyoto_Univ/update_portal.py` を実行し、共通シェルが反映されたことと、`Kyoto_Univ/index.html` の該当授業回に「解説」として登録されたことを確認する。
- 読者向けにMarkdownを重ねて保存するのは、ユーザーが求めた場合か、既存構成がMarkdown中心の場合に限る。`course-context.md` は管理用として維持してよい。

## 出力の構造

LIFE科目ページでは `mock.html` の画面構成を優先する。ヘッダー・パンくず・区切り線の下に開閉式「目次」を置き、目次パネルから要旨・章・各スライドへ移動できるようにする。記事は「講義を通して言いたいこと」から始め、章見出しの後に各スライドの「解説」と原スライド画像を同じ `.explanation-grid` で対応させる。独立した章別目次を要旨の下に追加したり、解説とスライド画像を別々の一覧に分けたりしない。

本文には科目・資料名、授業回と資料順（推定・不明なら明示）、原PDFへの参照、全体と各章・各枚の読了時間を含める。各枚に安定したアンカー、原典位置、短い主張、解説を置き、低優先度の枚には理由を一言添える。LIFE以外の環境では、ユーザー指定と既存の文書構成に従い、要旨・章別目次・章ごとの本文を読みやすい順に構成する。

判定根拠、確認した問題の範囲、用語の初回説明位置は `course-context.md` または既存の同等の管理記録に残す。読者の判断に必要な判定状態・資料不足・読了時間の前提は本文でも短く示す。

アンカーは `chapter-01`、`slide-001` など内容を変えても保てるものにする。複数PDFを同じ画面に置く場合は資料識別子を加えて衝突を避ける。画像を並べる場合は対応する原ページ・位置の画像を使い、再現図を原スライド扱いしない。

## 完了前の確認

- 全スライドが原順序で章と個別解説に対応し、ページ・印字番号・授業回・資料順を区別したか。
- 目次リンクと原典参照は有効で、確認済み・推定・不明を区別したか。
- 横のタブは `ui/shell.html` と一致し、科目間で項目・順序・アイコンが変わらないか。
- 未説明の用語・初出記号・必要な前提を補い、既出説明との重複を削ったか。
- 原文のコピーではなく意味・論理・用途を補い、LaTeX・条件・図の解釈が原典に合うか。
- 利用可能な問題を確認し、優先度と証明の詳しさに根拠があるか。
- 各枚・章・全体の読了時間が整合し、資料と用語の記録を更新したか。
