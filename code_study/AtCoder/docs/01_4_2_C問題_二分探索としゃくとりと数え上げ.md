## 4.4 二分探索 — ソート済みの列から O(log N) で探す

ソート済みのリストに対して「x はどこに入るか」を **O(log N)** で答える道具です。
標準ライブラリの `bisect` を使うので、自分で書く必要はありません。

```python
import bisect

A = [1, 3, 3, 5, 8]

bisect.bisect_left(A, 3)   # 1  ← 3 を入れるなら「いちばん左」の位置
bisect.bisect_right(A, 3)  # 3  ← 3 を入れるなら「いちばん右」の位置
```

```
   A  =  [ 1 , 3 , 3 , 5 , 8 ]
   位置   0   1   2   3   4   5    ← 挿入できる「すきま」の番号（先頭が 0）

   bisect_left(A, 3)  = 1   ← 同じ値のかたまりの左端
   bisect_right(A, 3) = 3   ← 同じ値のかたまりの右端
   差 3 - 1 = 2             ← 3 はちょうど 2 個ある
```

ここから次の 3 つが作れます。**この 3 つを暗記してください。**

```python
import bisect

# 1) x 未満の要素は何個あるか
bisect.bisect_left(A, x)

# 2) x 以下の要素は何個あるか
bisect.bisect_right(A, x)

# 3) x と同じ値は何個あるか
bisect.bisect_right(A, x) - bisect.bisect_left(A, x)
```

「x 以上の最小の要素」を取りたいときは `i = bisect.bisect_left(A, x)` として `A[i]`。
ただし **`i == len(A)`（x 以上の要素が無い）場合の場合分けを必ず書いてください**。
これを忘れると `IndexError` で RE します。

```python
i = bisect.bisect_left(A, x)
if i < len(A):
    print(A[i])      # x 以上で最小の要素
else:
    print("なし")
```

**必ず先にソートしておくこと。** ソートしていないリストに使うと、
エラーも出ずにデタラメな答えが返ります（いちばん見つけにくいバグです）。

### 使い方の典型：二重ループを潰す

```python
import bisect

# 例: A と B から 1 個ずつ選び、A[i] + B[j] <= X となる組の個数
N, X = map(int, input().split())
A = list(map(int, input().split()))
B = list(map(int, input().split()))

B.sort()
ans = 0
for a in A:                                # O(N)
    ans += bisect.bisect_right(B, X - a)   # O(log N)
print(ans)
```

素直にやれば O(N²) のところが、**外側のループ × 二分探索で O(N log N)** になりました。
「相手を探している二重ループ」を見たら、ソート＋`bisect` を疑ってください。

### 答えそのものを二分探索する（めぐる式二分探索）

配列の中を探すのではなく、**「答えの値」を二分探索する**こともあります。
使える条件は **「答えが x のとき条件を満たすか？」が O(N) 程度で判定でき、
かつ x について単調（ある境目から先は全部 True）であること**です。

```
   x:   1   2   3   4   5   6   7   8
 判定:  ×   ×   ×   ○   ○   ○   ○   ○
                    ↑ この境目を二分探索で探す
```

```python
# 「条件を満たす最小の x」を求める型
def check(x):
    # x で条件を満たすなら True を返す。ここは O(N) で書く
    ...

ng, ok = 0, 10 ** 18       # ng は必ず False、ok は必ず True になる端を置く
while abs(ok - ng) > 1:
    mid = (ok + ng) // 2
    if check(mid):
        ok = mid
    else:
        ng = mid
print(ok)
```

`ng` と `ok` の初期値を**絶対に条件を満たさない値／絶対に満たす値**に置くのがコツです。
（`ng, ok` を逆に置けば「条件を満たす最大の x」になります。）

計算量は `O(N log(答えの範囲))`。範囲が 10^18 でも log は 60 回なので、実質 60N です。

> **問題文に「最大値を最小化せよ」「最小値を最大化せよ」「K 個以上作れる最大の x」**
> という言い回しが出てきたら、この型を疑ってください。D 帯でもよく出ます。

## 4.5 しゃくとり法 — 区間を O(N) でなめる

「条件を満たす連続部分列の個数／最大長」を求める型。
**左端と右端の 2 つの位置を、どちらも後ろにしか動かさない**ので全体 O(N) です。

```python
# 例: 合計が K 以下になる連続部分列の個数（A の要素はすべて正）
N, K = map(int, input().split())
A = list(map(int, input().split()))

ans = 0
right = 0
total = 0
for left in range(N):
    while right < N and total + A[right] <= K:
        total += A[right]
        right += 1
    ans += right - left          # [left, right) が条件を満たす区間
    if right == left:            # 1 個も伸ばせなかった
        right += 1
    else:
        total -= A[left]         # left を 1 つ進めるので、その分を引く
print(ans)
```

```
   left も right も戻らない。だから移動回数の合計は高々 N + N = O(N)

   A = [ 1, 2, 3, 4, 5 ]   K = 6
        └left    right（開いた側）
          ──────→          ← right は伸ばすだけ
        ───→                ← left も進むだけ
```

二重ループに見えて O(N²) ではありません。**`right` が巻き戻らない**のがポイントです。

使える条件は「**左端を右にずらしたとき、右端も右にしか動かなくてよい**」こと。
上の例なら要素が全部正なので、left を進めれば合計は必ず減り、right はさらに伸ばせる側にしか動きません。
**負の数が混ざると単調性が崩れて使えません**。そのときは累積和＋二分探索を考えます。

`if right == left` の分岐は、「A[left] 単体ですでに K を超えている」ケースの処理です。
ここを書き忘れると `right < left` になって無限ループか WA になります。

## 4.6 数え上げの道具（`Counter` / `defaultdict` / `set`）

C 問題の半分くらいは「何かを数える」問題です。道具はこれで足ります。

```python
from collections import Counter, defaultdict

# Counter: 個数を数える
cnt = Counter(A)              # {値: 個数}
cnt[999]                      # 無いキーは 0（KeyError にならない）
cnt.most_common(3)            # 多い順に 3 個
cnt.items()                   # (値, 個数) を順に取り出す

# defaultdict: 初期値つき辞書
d = defaultdict(int)          # 無いキーは 0
d[key] += 1
g = defaultdict(list)         # 無いキーは []
g[key].append(x)              # いきなり append できる

# set: 存在判定 O(1)、重複除去
S = set(A)
len(S)                        # 種類数
x in S                        # O(1)
S1 & S2, S1 | S2, S1 - S2     # 積集合・和集合・差集合
```

**素の `dict` で `d[key] += 1` と書くと、初回に `KeyError` で RE します。**
`defaultdict(int)` か `Counter` を使ってください。

> `defaultdict` は「無いキーを読んだ瞬間に、そのキーが作られる」点に注意。
> `if d[key] == 0:` と書くだけでキーが増えるので、**存在確認は `if key in d:`** で行います。

### 「ペアの個数」の定番

「同じ値のペアは何組あるか」は、各値の個数 `c` に対して `c × (c-1) / 2` を足します。

```python
from collections import Counter
cnt = Counter(A)
ans = sum(c * (c - 1) // 2 for c in cnt.values())
print(ans)
```

二重ループ O(N²) で数えるところを、**数えてから組合せの式で出す** ことで O(N) になりました。
これは C 帯で非常によく出る発想です。

### 「条件を満たすペア」を式変形して数える

`A[i] + B[j] == X` のようにペアを数える問題は、**i と j を分離する**のが定石です。

```python
from collections import Counter

# A[i] + B[j] == X となるペアの個数
cntB = Counter(B)
ans = 0
for a in A:
    ans += cntB[X - a]      # 相手は X - a と決まっている → 数えるだけ
print(ans)
```

二重ループを回す代わりに、**「相手が何であるべきか」を式から決めて、辞書で引く**。
`A[i] - i == A[j] - j` のように**添字を含む式**も、左辺と右辺に分離できれば同じ手が使えます。

## 理解度チェック

<details>
<summary><b>Q1.</b> `bisect.bisect_right(A, x)` を呼んだのに、答えがまったく合わない。まず何を疑う？</summary>

**A.** **A がソートされていないこと**。`bisect` はソート済みを前提に半分ずつ範囲を絞るので、
未ソートだとエラーも例外も出さずにデタラメな位置を返す。
`A.sort()` を呼び忘れていないか、ソート後に `append` していないかを確認する。→ §4.4
</details>

<details>
<summary><b>Q2.</b> しゃくとり法は二重ループに見えるのに O(N)。なぜ？ 使えない入力はどんなとき？</summary>

**A.** `left` も `right` も**後戻りしない**ため、2 つの位置の移動回数の合計が高々 2N だから。
使えないのは「left を進めたときに right を戻す必要がある」場合、
たとえば **A に負の数が混ざっていて合計が単調に変化しない**とき。→ §4.5
</details>

<details>
<summary><b>Q3.</b> `d = {}` として `d[key] += 1` と書いたら RE した。原因と直し方は？</summary>

**A.** 存在しないキーを読もうとして `KeyError`。AtCoder 上では **RE** と表示される。
`from collections import defaultdict` して `d = defaultdict(int)` にすれば、
無いキーは 0 として扱われる。数えるだけなら `Counter` でもよい。
なお `defaultdict` は**読んだだけでキーが増える**ので、存在確認は `key in d` で行う。→ §4.6
</details>
