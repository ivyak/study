# 板書・手書きノートから授業回HTMLを作る

板書写真や手書きノートに書かれている内容を、そのまま読みやすい文章・数式・図に清書する。**本文には独自の解説を一切加えない。追加で文章を書けるのは冒頭の概要「講義を通して言いたいこと」だけ。** 原典の記述順、用語、記号、式変形、例題、注記を抜け漏れなく残す。既存ページはUIだけの参考とし、その詳しさに合わせて説明を増やさない。

## 入力と授業回の判定

対象画像・手書きPDFの全ページを確認する。科目情報、配布一覧、先行資料は、授業回・資料順・記法の照合に必要な範囲で確認する。写真は向き、切れ、重なり、左右の板書順を見て並べ、PDFの文字抽出やOCRは原画像と照合する。読めない記号・式・文章を文脈だけで確定しない。部分的に読めない箇所は位置と影響を記録し、確認できた範囲で本文を作る。読解上重要な欠落は読者にも短く示す。

科目、年度・学期、担当者、授業回、同じ回の資料順を別々に判定する。ユーザーの対応付け、原典中の明示、資料一覧・配布順、シラバス・日付、ファイル名、内容の連続性を根拠にし、項目ごとに `確認済み／推定／不明` と出典位置を管理記録へ残す。画像番号、ノートのページ番号、章番号を授業回と混同しない。複数回にまたがるノートは範囲ごとの対応を残す。内容の類似だけでは授業回を確定しない。授業回が推定・不明でも読めた内容のHTMLは作るが、ファイル名とメタデータで確定事項として扱わず、見える位置に判定状態を記す。

画像・PDFページは1始まりで原典位置を記録し、印字されたページ番号と区別する。1枚に複数の話題がある場合は範囲を、複数枚に同じ導出が続く場合は連続する原典位置を記録する。各画像を機械的に1節にせず、講義内容のまとまりで節を切る。原典の順序と、どの内容をどこから読んだかを失わない。

## 内容を清書する

冒頭の概要「講義を通して言いたいこと」だけは、原典全体を踏まえた1〜3文の要約を新たに書いてよい。入力が授業の一部ならその範囲を示す。概要でも原典にない知識・結論・解法は導入しない。

概要より後の本文は、原典に書かれていることだけを、元の順番どおり抜け漏れなく整える。許されるのは、手書き文字の活字化、改行・句読点・段落の整理、意味を変えない最小限の文法の整形、LaTeXへの置換、原典に沿った見出し付けである。単語や箇条書きで書かれた箇所に、原典にない意味付けや論理を補わない。節の先頭に独自の主張・要点・導入文を挿入しない。

次の内容は、役に立つ場合でも本文へ追加しない。「清書時の補足」、注、トグル、脚注などに分けても追加してはならない。

- 用語の定義、記号の説明、前提知識、前回の復習（原典にあるものはそのまま残す）。
- 原典にない途中式、証明、導出、検算、適用条件、例外、具体例。
- 「なぜ成り立つか」「何を意味するか」「どう使うか」という解説、学習上の助言。
- 演習のヒント、着眼点、解答、別解、過去問との関連付け。
- 原典の誤記らしい箇所に対する訂正式や解説。

原典の定義・仮定・式・導出・例題・問い・解答・注記は、重要度で省略せずすべて残す。問題や先行解説を根拠に本文の詳しさを変えない。原典に省略されている計算や説明は省略されたままとし、解答が書かれていない問いは問いのまま清書する。

原典の見出しを優先して章・節を作る。見出しがない場合だけ、内容を表す簡潔な見出しを付け、生成した区分であることを管理記録に残す。節分けのために内容の順序を入れ替えない。日付・反復を含め、全ページの内容がどこへ対応するかを管理記録に残す。

数式はテキストのLaTeXで書き、独立した式は表示用区切りで中央に表示する。原典の記号・条件・計算結果を保持し、数学的に誤って見えても黙って修正しない。疑わしい箇所は管理記録へ残し、本文では必要最小限の「原文どおり」の表示だけを添える。判読不能箇所は位置を保って「［判読不能］」と示し、推測で埋めない。これらの表示は清書の忠実性を示すためのもので、新たな解説を加える許可ではない。

図は原典のラベル・軸・向き・関係を忠実に描き直し、新しい説明用の図を創作しない。図中文字も欠かさず清書する。原図の描き直しであることは短い出典表示で示す。文字起こしを入力として併用する場合も、確認できた発話だけを整え、原テキストの位置・リンクを記録する。

出典・原典位置、判定状態、判読不能表示、読了時間、目次・共通UIは文書管理・表示に必要な情報として付けてよい。これらを使って内容の補足解説を追加しない。過去問未確認などの学習上の案内は付けない。

各節・章・回全体の想定読了時間を示す。日本語本文の毎分400〜600字を暫定目安とし、原典の数式・図の読解負荷を加える。演習や自力での証明・計算は含めない。章・全体は未丸めの節時間から合算し、概要と目次も全体へ含める。前提は冒頭に一度書く。

## LIFEのHTMLと保存

このリポジトリでは、指定がなければ読者向けHTMLを科目フォルダ直下の `第N回_内容.html` に保存する。授業回が確定していないときは元資料を識別できる名前にする。管理記録は同科目の `study/handwritten-explanations/course-context.md`、または既存の同等の記録へ置き、授業回の根拠、画像・ページと節の対応、判読不能箇所、原典の表記に疑義がある箇所を記す。管理記録を読者向けHTMLの代用にしない。先行回の変更が後続の参照に影響するなら該当箇所を確認する。

UIは `Kyoto_Univ/ui/mock.html` の授業資料リーダーを規範にする。科目ページの共通シェルは `Kyoto_Univ/ui/shell.html` だけから同期し、`<div class="shell">` と `<main>` の間を `<!-- LIFE-SHELL:START -->` / `<!-- LIFE-SHELL:END -->` で囲む。既存ページからサイドバーを固定コピーしない。パンくず、戻る導線、配色・余白、数式設定は`Kyoto_Univ/[2026後期木３]微分積分学続論II/第2回_同次形・完全形と線積分.html`と `Kyoto_Univ/ui/life.css`・`life.js` に合わせる。

上部の「＜」戻るボタンは、本文全体を含む `main` の直下に `.document-back > a.back-step` として置き、戻り先とアクセシブルな名前を設定する。共通の `Kyoto_Univ/ui/life.css` により、スクロール中も画面上端から30pxの位置に残る（`position: sticky`、幅52px、黒背景）。短いヘッダー内への配置や、資料HTMLでの追従スタイルの重複・上書きを避ける。PC・スマートフォン幅でスクロール後も表示され、戻り先へ移動できることを確認する。


戻る矢印は文字の `＜`・`<`・`&lt;`・`←` で代用せず、既存ページと同じ次のSVGを使う。文字で作るとフォントにより形・太さ・位置が変わる。`href` は対象科目の一覧に合わせ、`main` の直下に置く。

```html
<div class="document-back">
  <a class="back-step" href="../index.html#course=対象科目フォルダ名"
     aria-label="授業一覧に戻る" title="授業一覧に戻る">
    <svg class="ui-icon" viewBox="0 0 24 24" aria-hidden="true">
      <path d="m15 5-7 7 7 7"/>
    </svg>
  </a>
</div>
```

完了前に `.document-back > a.back-step > svg.ui-icon` と上の `viewBox`・`path` があること、文字の矢印を残していないことを確認する。表示でも既存ページと矢印の形・中央配置・52pxのボタンサイズを比較し、PC幅とスマートフォン幅でスクロール後の追従と戻り先を確認する。小さな資料やコード例だけの授業ページにも同じ共通UIを使う。


共通UIで本文の「未読・勉強中・完了」、第N回一覧では作成日の隣で縦位置をそろえた状態バッジ、時間割の白・青・緑の枠（未読の四角は金色）、小見出しのしおりを表示する。しおりは文字行と高さをそろえた小さな金枠の円とし、選択中は金色で塗る。星や資料HTML独自の操作UIを追加しない。資料固有の `.dot` などが共通UIのクラスと衝突しないよう確認する。

本文はヘッダー・パンくず・区切り線の後の `.reader` に、記事と開閉式 `<nav class="toc">` を置く。目次ボタンとパネルの動きはmockと同じにする。記事は `<section class="summary" id="summary">` の「講義を通して言いたいこと」から始め、章見出しと、内容ごとの `<section class="explanation" id="explanation-NNN">` を原順に続ける。目次パネルから要旨、章、各節へ移動できるようにする。各節には原典に沿った見出しと清書した本文を置く。「解説」という見出しや独自の短い主張は追加しない。CSSクラス名 `explanation` は共通UIとの互換性のため維持する。元の板書・ノート画像やPDFページはHTMLに埋め込まず、画像欄・空の `.slide`・画像の代替プレースホルダーも置かない。画像用の2列グリッドは使わず、文章と数式を本文の幅で表示し、原典の図を描き直したものだけを添える。原典を併記しないことを理由に、本文の説明を追加してはならない。出典名と節ごとの原典位置はテキストで示し、原典リンクが利用できる場合は必要に応じて付ける。

確認済みの授業回には `<meta name="study-lesson" content="N">`、`<meta name="study-kind" content="解説">`、`<meta name="study-created" content="YYYY-MM-DD">` を付ける。推定・不明の回に授業回メタデータを付けない。タイトルと見出しにも判定状態を正しく反映する。保存後に `python3 Kyoto_Univ/update_portal.py` を実行し、共通シェルと授業一覧の「解説」への登録、目次のリンク、数式、PC・スマートフォン幅での表示を確認する。読者向けMarkdownを重ねて保存するのは指定がある場合か、既存構成がMarkdown中心の場合に限る。

他の環境ではユーザーの出力形式・保存先と既存のUIを優先し、LIFE固有のHTML・メタデータを必須にしない。

## 完了前の確認

- 全画像・全ページを確認し、原典の文字・数式・図・注記・問いを抜け漏れなく清書したか。
- 原典の順序・用語・記号・省略を保ち、独自の説明・途中式・復習・ヒント・訂正を本文へ足していないか。
- 新たな要約文は冒頭の概要だけに限定し、各節の冒頭や補足欄へ追加していないか。
- 判読不能箇所と原文の疑義を推測で直さず、位置と状態を記録したか。
- 元画像・空の画像欄を残さず、共通シェル・目次・パンくず・戻る導線・数式表示を確認したか。
- 節・章・全体の読了時間、管理記録とポータルを更新したか。
