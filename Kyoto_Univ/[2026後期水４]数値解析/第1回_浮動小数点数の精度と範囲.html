原典：第1回の配布スライド写真の左下（印字番号13/21）。

このスライドで言いたいこと

単精度と倍精度では、保存するビット数を符号・小数部・指数部に分ける。小数部の先頭に補う「隠れた1」のため、有効数字のビット数だけが保存ビット数より1多い。この区別から、10進の精度と表現できる大きさの目安が読み取れる。

スライド13：浮動小数点数の構造 約4分

スライドの表で「全長」は実際に保存するビット数を指す。通常の有限な数は、符号 \(s\)、2進数の有効数字 \(1.f\)、指数 \(e\) を使って次の形で表す。

\[x=(-1)^s(1.f)_2\,2^e\]

\(f\) は小数点以下のビット列。たとえば \((1.01)_2=1+2^{-2}=1.25\) である。指数を変えると小数点の位置が動く。スライド上部の歴史の箇所は、この表現がIEEE 754として標準化されるまでの流れを短く示している。

種類実際に保存する内訳合計有効数字
単精度符号1 + 小数部23 + 指数部832ビット先頭の1 + 小数部23 = 24ビット
倍精度符号1 + 小数部52 + 指数部1164ビット先頭の1 + 小数部52 = 53ビット

なぜ全部足すと1ビット多く見えるのか

表の「小数部 \(1+23\)」「\(1+52\)」にある最初の1は、保存領域を1ビット増やす意味ではない。0以外の正規化された数は有効数字を必ず \((1.f)_2\) の形にできるため、先頭が1だと分かっている。そこで、その1をメモリには書かず、読み出すときに補う。これを隠れたビットという。

単精度なら「保存する数」\(1+23+8=32\)、「有効数字として使える数」\(1+23=24\)。\(1+(1+23)+8=33\) と足すと、保存しない先頭の1まで保存ビットとして数えてしまう。

先頭の1を補えるのは正規化された数の場合に限る。ゼロや、ゼロに近い非正規化数では先頭は \(0.f\) になり、同じ24ビット・53ビットの精度は得られない。

「非正規仮数」とは何か

仮数は \(1.f\) のように数の有効数字を担う部分である。正規化数では先頭が必ず1なので、1を省略して小数部 \(f\) だけ保存できる。一方、指数をそれ以上小さくできないところでゼロに近い数も表すには、先頭を0とみなして \(0.f\) を使う。これが非正規化数の仮数（非正規仮数）であり、新しい保存欄を増やすわけではない。

\[\text{正規化数：}\;(1.f)_2\,2^e,\qquad \text{非正規化数：}\;(0.f)_2\,2^{e_{\min}}.\]

非正規化数では指数を最小の \(e_{\min}\) に固定し、\(f\) の1の位置を右へずらして値を小さくする。単精度で \(e_{\min}=-126\) とすると、\(0.100\ldots0\times2^{-126}=2^{-127}\)。さらに右へずらした最小値は \(0.00\ldots01\times2^{-126}=2^{-149}\) となる。先頭に0が増えるぶん有効な1から先のビットが減り、ゼロに近いほど精度が落ちる。

スライド下の三つの問い 約6分

問1　10進で約7.2桁・16.0桁なのはなぜか

有効数字が \(p\) ビットなら、\(1\le x<2\) に並ぶ数の間隔は \(2^{-(p-1)}\)。最近値に丸める際の最大のずれは、その半分の \(2^{-p}\) である。この誤差の大きさを10進の桁数 \(d\) に換算するため、\(10^{-d}=2^{-p}\) とおくと \(d=p\log_{10}2\) になる。

\[\begin{aligned}p=24&:\quad 24\log_{10}2\approx7.22,\\p=53&:\quad 53\log_{10}2\approx15.95.\end{aligned}\]

倍精度では小数部が23ビットから52ビットへ増え、隠れた1を含む有効数字は24ビットから53ビットになる。増えた29ビットは \(29\log_{10}2\approx8.73\) 桁分なので、10進精度は約7.2桁から約16.0桁へ増える。有効数字の桁数を増やすのは小数部のビット数であり、指数部のビット数が増えると表せる数の大きさの範囲が広がる。

これが表の「約7.2桁」「約16.0桁」の由来。どんな10進数でもその桁数が必ず正しいという保証ではない。10進数を2進数に直すと無限に続くこともあり、丸めた値を演算すればさらに誤差が生じる。目安として、単精度は約7桁、倍精度は約16桁の有効数字を持つ、と読む。

問2　表現できる数の範囲とは何か

小数部は数字の細かさを、指数部は小数点をどれほど動かせるかを決める。指数部が8ビットの単精度では、正規化された数の指数は \(-126\le e\le127\)。11ビットの倍精度では \(-1022\le e\le1023\) となる。指数部のビット列をすべて通常の指数に使うわけではなく、ゼロに近い数や無限大・NaNなどのために一部を使う。

種類最小の正の正規化数最大の有限数最小の正の非正規化数
単精度\(2^{-126}\approx1.18\times10^{-38}\)約 \(3.40\times10^{38}\)\(2^{-149}\approx1.40\times10^{-45}\)
倍精度\(2^{-1022}\approx2.23\times10^{-308}\)約 \(1.80\times10^{308}\)\(2^{-1074}\approx4.94\times10^{-324}\)

最大有限数の \(3.40\) と \(1.80\) はどこから来るか

最大値にするには、指数を最大にし、小数部 \(f\) のビットをすべて1にする。単精度の小数部は23ビットなので、仮数は \((1.111\ldots111)_2=2-2^{-23}\)。倍精度では52ビットなので \(2-2^{-52}\) になる。

\[\begin{aligned} \text{単精度の最大値} &=(2-2^{-23})\,2^{127} =(1-2^{-24})\,2^{128} \approx 3.4028235\times10^{38},\\ \text{倍精度の最大値} &=(2-2^{-52})\,2^{1023} =(1-2^{-53})\,2^{1024} \approx 1.7976931\times10^{308}. \end{aligned}\]

係数 \(3.40\)、\(1.80\) は \(2\) のべき乗を10進表示した結果である。たとえば \(2^{128}\approx3.4028237\times10^{38}\) で、実際の最大値はこれより少し小さい。「\(10^{38}\) まで」というだけでは係数を落としているので、表では桁の目安として読めばよい。

スライドの \(10^{\pm38}\)、\(10^{\pm308}\) は、正規化された数についての桁単位の目安である。たとえば単精度の「\(10^{-38}\)」より小さい正の数も非正規化数で表せるが、ゼロに近づくほど有効数字は減る。また、表の範囲内にある実数をすべて正確に表せるわけではない。

問3　倍精度の計算結果は常に単精度より正しいか

一つの実数をそれぞれの形式へ最近値丸めするだけなら、倍精度のほうが単精度以上に元の値へ近い。ただし、複数の演算では各段階で丸めが入り、誤差が増幅したり、偶然打ち消し合ったりする。したがって最終結果が常に倍精度のほうが真値に近いとは言えない。

たとえば、十進数としての真値が \(0.1\times3-0.3=0\) である計算を、それぞれの精度で各演算を丸めながら行うと、単精度では \(0\)、倍精度では \(5.551115123125783\times10^{-17}\) になる例がある。単精度の誤差がこの式では偶然打ち消された。もちろん一般には、倍精度のほうが丸め誤差を小さくしやすい。

計算を評価するときは「何ビット使ったか」だけでなく、真値との差、引き算による桁落ち、問題そのものの誤差への敏感さも見る。
