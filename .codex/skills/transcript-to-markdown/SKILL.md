# トランスクリプトの全文整文

## 成果物と保存先

入力の発言内容をすべて保持した、自然な日本語のMarkdownを作る。話題に沿った見出しを付け、元の発言順に読める文章に整える。内容の重要度で収録対象を選別しない。

ユーザーの指定がなければ、原ファイルと同じフォルダに `<元ファイルの拡張子を除いた名前>_整文.md` を保存する。たとえば `Kyoto_Univ/[2026後期火１]熱力学/熱力学 第1回.txt` なら `熱力学 第1回_整文.md`。原ファイルは変更しない。既存の整文を更新するときも入力原文と照合する。原文と無関係な既存ファイルは上書きしない。

Markdown単体で読める成果物とし、HTML化、ポータル更新、要約・学習問題・補足解説の追加は依頼されたときだけ行う。

## 「内容を一切失わない」の扱い

- 主張、理由、説明、例、比喩、導出、途中計算、数値、単位、条件、例外、留保、否定、質疑応答、余談、雑談、授業や試験の連絡、冒頭・末尾の発言をすべて残す。「本筋ではない」「既出だから」を理由に削らない。
- 同じ話を再度説明した部分は、その位置で残す。別の箇所への統合や並べ替えによって、繰り返し、強調、説明の流れを失わせない。
- 削ってよいのは意味を持たないフィラー（「あの」「えっと」など）と、発音のつかえ・直後に言い直された同じ語の断片だけ。「まあ」「たぶん」「と思う」などが確信の程度や留保を表すときは残す。迷う場合は残す。
- 内容を伴う言い直しは両方を残し、「体積一定、ではなく圧力一定の場合です」のように訂正関係を示す。異なる説明を一つの正しい説明にまとめない。
- 発言者の見解、疑問、推測を、確定した一般的事実へ変えない。意味・因果・条件・確信の程度が保たれる範囲で語尾や語順を整える。

ここでいう整文は逐字転記ではない。逐字保存も指定された場合はフィラーやつかえも削らず、句読点・空白・段落・見出しの調整を中心にする。

## 原文の読み込みと対応確認

1. 対象ファイルと指定範囲を確認し、文字コード・総文字数を調べる。パスに空白や角括弧がある場合は正しく引用する。指定範囲がなければ全文を対象にする。
2. 原文を先頭から末尾まで読む。長い1行の文字起こしは行番号だけで分割しない。文字位置で数千字ずつ読み、文末や話題の切れ目を考慮して処理区間を決める。ツール出力が省略された場合は、見えなかった範囲を再読する。
3. 作業用に、各区間の文字範囲 `[開始, 終了)`、話題、整文先の見出し／段落、不明箇所を控える。範囲が先頭の0から末尾の総文字数まで隙間なく連続することを確認する。文脈確認用の重複読みを、本文の二重収録につなげない。
4. 区間ごとに整文し、原文の各発言の意味が本文のどこに残ったか照合する。長文を一度に短縮生成してから不足を補う進め方は避ける。
5. 結合後に全文を再照合する。区間の処理済み記録だけで内容保持を保証したことにしない。区間の境界で文や訂正が途切れていないかも確認する。

文字数や段落数の一致は内容保持の証明にならない。出力制限で一度に処理できない場合も、ファイルへ順次保存して最後まで続ける。入力欠損などで未処理部分が残るときは完成扱いせず、未処理範囲を明示する。

## 整文と見出し

- 日本語の語中に入った不要な空白を取り、句読点を補う。英単語の区切り、記号、数値と単位の関係は壊さない。
- 文脈から一意に復元できる助詞・接続・語尾だけを補い、段落内の文が自然につながるようにする。原文が断片的なら、その断片性を無理に解消しない。
- `#` に資料名、`##` に話題、必要に応じて `###` に小話題を置く。話題が切り替わる位置で見出しを入れる。同じ話題が後で再登場しても、その場に見出しを付けて順序を保つ。
- 見出しはその箇所で実際に述べた内容を表す。断定できない用語や数式を見出しで確定させない。目次は長文の移動に役立つ場合に付けるが、要約で本文を代替しない。
- 本文は段落のある文章を基本とする。元が列挙なら箇条書き、対話なら話者表示を使ってよい。話者名が不明なら役割や名前を創作しない。
- 指示語（「この線」「こちら」など）は参照先が原文から確定するときだけ言い換える。図が入力にない場合、図の形や値を創作せず「この線〔参照図は入力に含まれない〕」などと残す。
- 入力にあるタイムスタンプ、話者ラベル、ページ参照は対応する位置に残す。授業日・教員名など、入力から分からないメタ情報を推測で追加しない。

## 誤認識・不明箇所・数式

音声がない場合、確認できるのは文字起こしに記載された内容までである。不明な発言を一般知識や周辺の授業資料から断定して復元しない。

- 句読点・空白以外の誤認識修正は、同じ入力内の明確な表記やユーザー指定の原資料で裏付けられる場合に限る。専門用語・人名・書名・数値・数式の修正は、元表記と根拠を「表記修正・要確認箇所」に残す。繰り返す同一修正はまとめてよい。
- 候補が推測にとどまるときは `〔要確認：原文「…」。候補：…〕` と書き、候補なしでもよい。意味を取れない断片は `〔原文不明瞭：「…」〕` として、その位置に該当原文を残す。「判読不能」だけに置き換えて原文を消さない。
- 数式は確実に読める場合だけインライン数式や独立数式に整える。添字、正負、係数、積分範囲、単位、等温・定圧などの条件を保存する。読めない式を教科書の標準式に置き換えない。
- たとえば `U - PS` を、熱力学では普通こうなるという理由だけで `U - TS` に変えない。根拠がなければ元表記を残して要確認とする。
- 原文自体の誤りや矛盾を勝手に修正しない。両方の発言を残し、必要な場合だけ「原文内で表記／説明が一致しない」と短く注記する。内容の正誤解説は依頼されたときに分離して行う。

## 出力の形

```markdown
# 元の資料名（整文）

原文：[元ファイル名](相対パス)

<!-- 整文方針：意味を持たないフィラーと発音のつかえのみ整理。不明箇所は原文を併記。 -->

## 最初の話題

整えた本文。

## 次の話題

整えた本文。

## 表記修正・要確認箇所

必要な場合のみ、本文の該当見出しと元表記、修正根拠や未確定事項を記す。
```

入力が貼り付け文なら原ファイルへのリンクは不要。見出し数・段落数・総文字数に上限を設けない。本文内の不明断片は、末尾の一覧へ移すために削除しない。

## 完了確認と報告

- 全区間が処理済みで、冒頭・末尾・区間境界に脱落がない。
- 本文を原文と順に照合し、例、連絡、余談、反復、訂正、留保も残っている。
- 数字・数式・固有名詞・否定・条件を照合し、根拠のない復元や外部知識の追加がない。
- 見出しの階層、Markdownの数式やリンク、不明箇所の原文併記を確認する。

最後に作成したMarkdownへのリンクと、要確認箇所があればその旨を短く伝える。原音声を照合していないのに「発言を完全復元した」とは報告しない。
